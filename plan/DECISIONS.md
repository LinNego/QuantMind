## 2026-11-16 · 定盘

### 输入

| 项 | 值 |
|---|---|
| 终点 | 2027-03-31 前拿到 Agent 岗面试；3 月整月面试 |
| 时间 | 每周 10–15 小时（每天 1–2 小时），加速日 3 小时 |
| 优先级 | 量化 > ML > Agent > LLM，要求融合而不是并列 |
| 现状 | 能读中型 Python 项目、调过 LLM API；无可用 GPU（仅 2G 1050），2 月租卡 |

### 采纳

| 决定 | 理由 |
|---|---|
| **7 节点 + 1 周缓冲 + 3 月面试** | 104 天 ÷ 14 天 = 7.4，节点与 deadline 天然对齐 |
| **2 周一个节点** | 14 天是「能出东西」和「能及时止损」的平衡点；4 周跑到第 3 周才发现方向错，已沉没 30 小时 |
| **内容不缩，日历弹性** | 时间可压，条目不可删。快出来的时间变缓冲，不变成更高的目标 |
| **每个节点先出 v0** | v0 出来当天就能发现问题，v1 是修出来的 |
| **不提前给详细计划** | 节点 N 过关才写 N+1。避免手上堆一堆用不上的表格 |
| **结算三件套 + 一个错** | 「指不出自己犯的错」= 在收集知识，不在长判断力 |
| **旧材料归档到 `_archive/`** | 作废但不删，git 历史仍在 |
| **节点 1–2 占 4 周（量化地基最厚）** | 它是后面所有数字可信度的来源，不能薄 |

### 否掉

| 选项 | 为什么否 |
|---|---|
| L0–L4 五级能力体系 | 引入与目标无关的分级，增加理解成本 |
| 原 16 周路线 | 配比反了：量化为主轴、Agent 为杠杆；目标是 Agent 岗，主轴应反过来 |
| 「4 周内容压成 2 周做完」 | 结果是 5 张浅表 + 零判断力。改为：靶子变小或日历顺延，不压缩单件深度 |
| 事件抽取项目（标 200 条） | 太慢，1 个月内做不完 |
| 多空辩论 Agent | 没有 ground truth，做不出可信评测；只读不建 |
| LLM 预训练 / 从零实现 Transformer | 240 小时里最多 20 小时给它；只做 LoRA SFT + 评测 |
| 深度学习时序选股（LSTM/Transformer） | 投入产出比低，且不是 Agent 岗考点 |

### 风险与对策

| 风险 | 对策 |
|---|---|
| 高强度（3h/天）只撑得住 2 周 | **只用在节点 1**（冷启动需要势能），之后回 1–2 小时/天 |
| Agent 动手时间被压到 1 月中 | 每周五花 30 分钟把本周产出包成函数，攒工具箱 |
| 2 月租卡踩坑 | 本地先写好代码、API 验证逻辑，上卡只做训练；预算 ¥50 打底 ¥100 封顶，集中租 2–3 天 |
| 「感觉学了但说不出来」 | 验收必须能演示：指出自己某个数字里的错 |
