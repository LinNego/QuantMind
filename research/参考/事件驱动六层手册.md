# 事件驱动六层手册（L0–L5）

> 你说的 L1~L6 就是这个，共六层。本文用 **L0~L5** 编号，因为 L0（原始数据）最容易被漏掉，
> 而它恰恰是未来函数的高发区。编号差一位，层数一样。
>
> 这份手册和《事件驱动系统总览》的分工：总览讲**为什么**，这份讲**每层具体怎么做、怎么验**。

---

## 怎么读

每一层回答一个问题，产出一张表，有一个基线，有一组验收。

跳着读没用——**上一层的表结构决定下一层能算什么**。
比如 L1 没存 `evidence`，L2 就没法按"消息强度"排序；L0 没存 `first_seen`，L5 的复现永远做不了。

六层的输出表连起来是一条链：

```
L0 原始表 ──→ L1 事件表 ──→ L2 信号表 ──→ L3 持仓表 ──→ L4 成交表 ──→ L5 指标表
```

---

## L0 · 原始层：数据在「当时」是什么样

**回答**：站在某一天收盘后，我能看到什么？

### 输出表

| 表 | 关键字段 | 说明 |
|---|---|---|
| `kline` | symbol, d, open/high/low/close, volume, amount, prev_close | **不复权**，用于涨跌停/成交判定 |
| `px` | symbol, d, close, r | **前复权**，用于算收益 |
| `cal` | d, seq | 交易日序列，事件时间的唯一口径 |
| `mkt` | d, mkt_r | 全市场等权收益，事件研究的基准 |
| `doc_archive` | doc_id, source, **publish_time, first_seen**, url, raw_text, hash | 文本层，`first_seen` 是命门 |

### 三条硬规则

1. **回测只能用 `first_seen`**（我们抓到的第一时间），不能用 `publish_time`（原文声称的时间）。
   新闻转载、延迟推送会让 publish_time 变成未来信息。
2. **收益用前复权，成交判定用不复权**。混用是 A 股最常见的低级错误。
3. **停牌日不能当 0 收益**。要么剔除，要么单独标记——否则持有期天数会算错。

### 基线

全市场等权（`mkt`）。所有评估都拿它比，不用沪深 300——小盘事件用 300 做基准会系统性高估。

### 验收

任取一天，问自己：**"这一天收盘后，我能看到的每一列，是不是当天真的可得？"**
答不上来的列，就是未来的信息。

### 代码

`tools/build_event_cache.py`（cal / px / mkt / kline）、`tools/pull_announcements.py`（doc_archive）

## L1 · 事件层：发生了什么

**回答**：谁、什么时候、什么事、多强。

### 输出表

| 字段 | 要求 |
|---|---|
| `event_id` | 唯一 |
| `symbol` | 后缀式 `600519.SH` |
| `event_date` | **事件发生日**，不是抓取日 |
| `event_type` | 封闭枚举，先定 20 个 |
| `direction` | pos / neg / neutral |
| `magnitude` | 幅度（送转股数、合同金额、解禁比例） |
| `evidence` | 原文片段，**必填**，能自动校验是原文子串 |
| `extractor` | `rule_v1` / `llm_xxx_v2`，版本必须记 |

### 三种实现，成本差 100 倍

| 类型 | 例子 | 怎么来 | 成本 |
|---|---|---|---|
| **日历型** | 除权除息、解禁、财报披露 | 查结构化表 | 半天 |
| **半结构化** | 重大合同、回购、减持、诉讼 | 公告已有 `ann_type` 字段，筛一下 | 半天 |
| **纯文本** | 政策、订单细节、供应链 | LLM 抽取 + evidence 校验 | 2~4 周 |

**先查清楚属于哪一类**。合同公告我原以为是第三类，实际是第二类——东财的 `ann_type` 已经分好了，
L1 变成一句 SQL。

### 基线

正则 + 枚举筛选，不上 LLM。LLM 只在它能证明比正则强时才上——而"证明"需要基线。

### 验收

| 项 | 标准 |
|---|---|
| L1 类型/是否发生 | 精确率 > 95%（200 条人工 gold） |
| L2 时间戳 | **100%**，从原文/公告时间取，不让模型猜 |
| L3 幅度/方向 | 70~80% 够用 |
| evidence 校验 | 100% 是原文子串，否则该字段置空 |

### 典型错误

- 事件日用了抓取日 → 未来函数
- 同一事件被多源转载重复计数
- 一对多映射（政策 → 个股）当成一对一
- 更正公告没处理，用了旧版本

## L2 · 信号层：该不该买

**回答**：这个事件对应哪只票、什么方向、赚多少、拿多久。

### 输出表

| 字段 | 说明 |
|---|---|
| `date` | 信号生成日（= 可交易日的**前一天**） |
| `symbol` | |
| `score` | 排序分（越高越买） |
| `expected_excess` | 预期超额，% |
| `horizon` | 预期持有天数 |

### 三种信号，按复杂度

1. **规则**：事件后第 N 天买、持有 M 天（除权除息、送转就是这么做的）
2. **打分**：按事件强度分档（送转力度、合同金额/营收比、解禁比例）
3. **概率**：预测"未来 k 天会不会发生"——**埋伏的核心**

### 基线

**同类事件的历史平均 CAR**。所有复杂信号都必须打败它。

### 验收（四问，缺一不可）

| 问题 | 标准 | 不过怎么办 |
|---|---|---|
| 方向对吗 | CAR 符号与假设一致 | 反过来想，或杀掉 |
| 显著吗 | 聚类 t > 2.5 | 加样本 / 换特征 / 杀掉 |
| 是真信号吗 | 安慰剂对照显著 | 大概率是市场 beta |
| 赚得够吗 | 覆盖双边成本 | 缩容量 / 杀掉 |

### 典型错误

- 用 LLM 的输出直接当分数（不可复现、不可审计）
- 用"事件后"的数据算信号（前视）
- 把"事件发生了"当成"事件可预知"（埋伏最常见死法）
- 只做全样本，不分年

### 代码

`tools/event_study.py`（CAR / 持有窗口 / 分组 / 聚类 t / 安慰剂）

## L3 · 组合层：买多少

**回答**：同时有几个信号？每个占多少资金？

### 输出表

| 字段 | 说明 |
|---|---|
| `date` | |
| `symbol` | |
| `weight` | 目标权重 |
| `reason` | 进场原因（哪条事件） |

### 规则（先简单）

- 固定仓位数 N（用 12），每仓 1/N
- 信号数 > N 时按比例缩到满仓
- 同一只票不重复建仓
- 报告**资金占用**（不是年化）

### 基线

等权持有 N 天。

### 验收

| 项 | 为什么重要 |
|---|---|
| 平均同时持仓数 | 决定分散度 |
| **资金占用** | 季节性策略只占 30%，年化不能和满仓策略比 |
| 最大同时持仓 | 决定容量上限 |

### 典型错误

- 把"有仓即满仓"的年化当成账户收益（虚高 2~3 倍）
- 用全样本挑仓位参数
- 忽略事件的时间聚集（财报季一天几十个信号，平时零个）

## L4 · 执行层：真能成交吗

**回答**：想买的买得进吗？想卖的卖得掉吗？扣完还剩多少？

### 输出表

| 字段 | 说明 |
|---|---|
| `date`, `symbol` | |
| `fill_price` | 实际成交价 |
| `fill_ratio` | 成交比例（涨跌停、停牌时为 0） |
| `cost` | 佣金 + 印花税 + 滑点 |
| `reason` | 未成交原因（涨停/停牌/流动性） |

### 必须模拟的五件事

1. **涨停买不进**（收盘价 ≥ 涨停价且封在最高）
2. **跌停卖不出**
3. **停牌**
4. **流动性**：日均成交额下限
5. **成本**：佣金 0.025% + 印花税 0.05%（卖出）+ 滑点 0.05~0.1%/边

### 基线

固定滑点 + 固定费率。不要一上来就搞冲击成本模型，先看固定成本下还赚不赚。

### 验收

| 项 | 送转实例 |
|---|---|
| 可交易比例 | 5,048 → 4,074（**80.7%**） |
| 买不进 | 1.8% |
| 卖不出 | 3.3% |
| 流动性不足 | 15.1% |
| 盈亏平衡成本 | 1.17% |

### 典型错误

- 假设收盘价一定成交
- 忽略涨停（A 股事件股最容易封板）
- 用固定滑点却报告很高的年化（说明容量没算）

## L5 · 评估层：赚没赚、稳不稳

**回答**：这个事件值不值得继续做。

### 输出表

| 指标 | 说明 |
|---|---|
| 年化 / 夏普 / 最大回撤 | 账户口径，含空仓 |
| 胜率 / 盈亏比 | 单笔分布 |
| 资金占用 | 别让读者误解年化 |
| 分年收益 | 逐年 vs 基准 |
| 分段收益 | 2016-2020 / 2021-2022 / 2023-2026 |
| 安慰剂 | 随机日期的同一策略 |
| 容量 | 单笔金额 / 日均成交额 |

### 基线

同期全市场等权。

### 四道门

| 门 | 问题 | 不过怎么办 |
|---|---|---|
| A 数据 | 能 point-in-time 复现吗 | 回 L0 |
| B 统计 | 聚类 t > 2.5，安慰剂显著 | 回 L2，或杀掉 |
| C 交易 | 扣成本 > 0，容量够 | 回 L4 |
| D 稳定 | 不靠单一年份 | 判定过拟合，回 L2 |

### 典型错误

- 只报总收益，不报分段（2023 后失效的策略看着像永动机）
- 不做安慰剂（随机日期也能赚 0.24%，把 1.24% 当成了全部 alpha）
- 用样本内最优参数报结果

## 两个已跑案例的对照

| | 除权除息（送转） | 重大合同 |
|---|---|---|
| L1 类型 | 日历型（查表） | 半结构化（`ann_type`） |
| L1 事件数 | 5,335 | 3,855 |
| L2 结论 | 事件前 5 天买入，CAR +2.48%（t=7.5） | 公告日见顶 +0.82%，T+1 后负漂移 |
| L2 判定 | 有时段性 alpha，2023 后消失 | **直接杀掉** |
| L3 | 12 仓等权，资金占用 29~40% | 未做（L2 已否） |
| L4 | 可交易 80.7%，盈亏平衡 1.17% | 未做 |
| L5 | 2016-2020 +15%、2021-2022 +24%、2023-2026 +9.7% | 未做 |

**对照的意义**：合同公告在 L2 就死了，省掉 L3/L4/L5 的全部工作。
这就是分层评估最实际的收益——**早死早超生**。

## 每层验收清单（打印出来用）

```
L0  □ first_seen 有吗      □ 前复权/不复权分开了吗   □ 停牌处理了吗
L1  □ 事件日=发生日        □ 类型是封闭枚举吗        □ evidence 可校验吗
L2  □ 聚类 t>2.5           □ 安慰剂做了吗            □ 方向对吗
L3  □ 报了资金占用         □ 同一票不重复建仓        □ 持仓数上限
L4  □ 涨停买不进           □ 跌停卖不出              □ 盈亏平衡成本
L5  □ 分年                 □ 分段                    □ 容量
```

## 一句话总结每层

| 层 | 一句话 |
|---|---|
| L0 | 存成「当时能看到的样子」 |
| L1 | 说清「发生了什么」 |
| L2 | 判断「该不该买」 |
| L3 | 决定「买多少」 |
| L4 | 变成「真成交」 |
| L5 | 算账「到底赚没赚」 |
