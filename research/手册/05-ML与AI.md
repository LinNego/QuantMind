## 1 量化就是监督学习（只是一直没人这么叫）

### 1.1 同一个方程

```
y_{i,t+h} = f(x_{i,t}) + ε

x：T 日能看到的全部信息（因子、事件、文本、财务）
y：未来 h 日收益（绝对 / 超额 / 截面排名）
f：你要找的映射
```

这就是标准监督学习。**量化不是「用 ML 炒股」，而是「炒股这个问题本来就长成 ML 的样子」。**

### 1.2 四步对应

| ML | 量化 |
|---|---|
| 特征工程 | 因子构造（02） |
| 标签 | 未来收益（本章 §2） |
| 训练/验证/测试 | 时间切分 + 样本外（本章 §3） |
| 模型选择/正则 | 因子筛选、加权、约束（02/03） |
| 评价指标 | IC、分层、成本后收益（不是 MSE） |

### 1.3 手写权重就是一个线性模型

```
score = 0.4·z(反转) + 0.3·z(低波) + 0.3·z(小市值)
```

这是一个 **3 特征、权重靠人定的线性模型**。IC 加权 ≈ 用历史 IC 当权重；等权 = 无信息先验。
**所以「多因子合成」和「训练一个模型」是同一件事的两种做法：一个权重靠人，一个权重靠数据估。**

### 1.4 ML 多给了什么（只有四条）

1. **自动定权重**：不用拍脑袋。
2. **非线性/交互**：小市值 × 低波、动量 × 流动性，人手写不出来。
3. **高维**：50~200 个因子，人手加权必崩，树模型能筛。
4. **统一评价**：特征重要性、OOS 曲线，把「我觉得」变成可检验。

ML **没有**给你：更多数据、更高信噪比、更稳的规律。**这三样才是量化的瓶颈。**

## 2 标签设计：一半的 ML 失败在这里

### 2.1 五种标签

| 标签 | 公式 | 优点 | 缺点 |
|---|---|---|---|
| 绝对收益 | `P_{t+h}/P_t − 1` | 直观 | 受市场整体涨跌影响 |
| 超额收益 | `r_i − r_benchmark` | 剔除 β | 基准选择影响大 |
| **截面排名** | `rank(r_i)` 每天 | 稳健、抗极值 | 丢失幅度信息 |
| 分类 | 涨/跌、前 30%/后 30% | 简单 | 阈值主观、不平衡 |
| 多任务 | 同时预测 5/10/20 日 | 信息共享 | 更复杂 |

**推荐**：截面排名（或 z-score）做回归，评价用 IC。
**理由**：量化要的是排序，不是精确点位；排名对极值和市场整体波动更稳健。

### 2.2 三个标签陷阱

**陷阱一：重叠窗口**

```
T 日标签 = 未来 5 日收益
T+1 日标签 = 未来 5 日收益（重叠 4 天）
```

后果：相邻样本高度相关，模型「记住」了同一段行情，验证集虚高。
解法：**purged 切分 + embargo**（见 §3）。

**陷阱二：标签泄漏**

- 用了 `future_return_*` 列当特征（仓库 `technical_indicators` 表里真有）
- 用了「事后修正」的财务数据
- 用了当前成分股/行业分类

**陷阱三：极端值**

未来 5 日收益可能有 +50%（连续涨停）和 -30%（暴雷）。
不处理 → 回归被极值主导。处理：**先做截面 rank，或 winsorize**。

## 3 时序交叉验证：随机切分是灾难

### 3.1 为什么不能随机切

```
随机切分 → 训练集里有 2024 年的样本，测试集里有 2024 年的样本
→ 模型「见过」测试期的市场环境
→ 样本外看起来很好，实盘立刻崩
```

金融数据有时间顺序，**未来不能用来预测过去**。

### 3.2 三种正确切法

| 方法 | 做法 | 适用 |
|---|---|---|
| **Holdout** | 前 70% 训练，后 30% 测试，中间留 gap | 最简单，必须做 |
| **Walk-forward** | 滚动窗口训练 → 预测下一段 → 前移 | 模拟真实更新 |
| **Purged K-Fold** | 分 K 折，删掉与测试集标签重叠的训练样本，加 embargo | 样本少时用 |

```python
# Holdout + embargo 的最小实现
split = int(len(dates) * 0.7)
gap = 5                                   # 标签窗口长度
train_idx = dates[:split - gap]
test_idx  = dates[split:]
```

**embargo**：训练集末尾和测试集开头之间，空出至少一个标签窗口，防止标签重叠。

### 3.3 样本外只跑一次

- 跑第二次，它就变成样本内了。
- 要调参？在训练集内部再切一个验证集。
- **测试集的唯一用途是「最后看一眼」。**

## 4 模型族：从线性到树，够用就停

| 模型 | 适合 | 优点 | 坑 |
|---|---|---|---|
| **线性回归 / Ridge** | 因子少、要可解释 | 稳定、系数即权重 | 非线性弱 |
| **Lasso** | 因子多、要筛选 | 自动稀疏 | 相关因子随机选一个 |
| **LightGBM / XGBoost** | 表格数据（默认首选） | 强、快、能处理缺失 | 容易过拟合，需早停 |
| **CatBoost** | 类别特征多 | 类别处理好 | 慢 |
| **排序模型（LambdaRank）** | 直接优化排序 | 目标与 IC 一致 | 实现复杂 |
| **TCN / Transformer** | 序列、高频、多市场 | 表达能力强 | 数据不够就是灾难 |

**结论**：**表格数据，LightGBM 是默认答案。**
不需要标准化、能处理缺失、训练快、有特征重要性。用它把流程跑通，再考虑换模型。

### 4.1 排序目标：为什么不用 MSE

- MSE 优化的是「点位准确」，但你要的是「排序正确」。
- 一只股票预测 +5%、实际 +10%，另一只预测 +1%、实际 +2%——MSE 惩罚前者，但排序是对的。
- 实务做法：**回归 + 截面 rank 标签 + 用 IC 评价**；或直接用排序损失。

## 5 评价：只看 IC 和成本后收益

| 指标 | 怎么看 | 判据 |
|---|---|---|
| **Rank IC** | 预测排名与未来收益排名的相关 | ≥ 规则版，且 OOS 稳定 |
| **ICIR** | IC 均值/标准差 | ≥ 0.2 |
| **分组收益** | 按预测分 5 组 | 单调 |
| **换手** | 预测排名变化率 | 不高于规则版太多 |
| **成本后收益** | 扣成本 | 这才是最终指标 |
| **分年稳定性** | 逐年 IC | 不能只靠一年 |

**不要看**：训练集 MSE、准确率、AUC。它们和赚钱没关系。

### 5.1 模型 vs 规则：一张诚实的对比表（数字为量级示例）

| | 规则版（等权 5 因子） | LightGBM 版 |
|---|---|---|
| 样本内 IC | 0.048 | 0.072 |
| 样本外 IC | 0.041 | 0.045 |
| 样本外 ICIR | 0.31 | 0.34 |
| 年换手 | 600% | 900% |
| 成本后年化 | 9.2% | 9.0% |
| 最大回撤 | -22% | -25% |

**读法**：模型样本内提升很大（0.048→0.072），样本外只提升 0.004，换手还高了，**扣完成本可能还不如规则版**。
**这是正常结果，不是失败。** 敢说「模型没带来价值」，比硬吹一个 0.01 的提升更专业。

## 6 特征工程与正则：模型之外的决定因素

### 6.1 时间衰减样本权重

越近的样本越重要：

```python
half_life = 250  # 一年
w = 0.5 ** (age_days / half_life)
```

**效果**：模型更适应当前市场，代价是有效样本变少。

### 6.2 特征数量 vs 样本量

经验法则：**每个特征至少 100~200 个独立样本**。
2500 个交易日 → 特征数控制在 10~25 个（如果按日频独立算）。
但横截面有 5000 只股票，样本量看似很大，**实际独立样本仍是「天数」级别**。

### 6.3 正则与早停

- `min_data_in_leaf` 调大（如 500）
- `num_leaves` 调小（如 31）
- `feature_fraction` / `bagging_fraction` < 1
- **早停必须用验证集，不能用测试集**

### 6.4 特征重要性的陷阱

- 重要性高 ≠ 有用（可能只是和另一个特征共线）
- 重要性基于训练集，不能证明 OOS 有效
- **正确用法**：用它反推「模型在用什么」，再和你的经济逻辑对照

## 7 集成与 regime：不是所有时候都信同一个模型

仓库的三层融合是个好例子：
[`fusion_config.py`](../../backend/services/engine/services/fusion_config.py)

| 市场状态 | LightGBM 权重 | TFT 权重 | 逻辑 |
|---|---|---|---|
| normal | 0.65 | 0.35 | 常态信树模型 |
| trending | 0.40 | 0.60 | 趋势市信序列模型 |
| volatile | 0.80 | 0.20 | 高波动信稳健的树模型 |

**这仍然是第 2 站（预测）的工作**：把多个模型的输出按状态加权。
**关键**：状态判断本身要简单、可解释（如波动率分位），不要再用一个模型去判断状态。

### 7.1 集成的三个层次

1. **模型内集成**：bagging、early stopping 的多轮平均
2. **模型间集成**：LGBM + 线性 + 序列，按验证集表现加权
3. **信号集成**：模型分 + 规则分 + 事件分，按 IC 加权

**每加一层，可解释性下降一档。** 散户做到第 2 层就够。

## 8 文本与非结构化：AI 到底在哪一格

### 8.1 一句话

> **「非结构化 → 结构化」不是预测，是造列。它发生在第 1 站（L1），产出的是特征，不是信号。**

| 输入 | 输出（列） | 用在哪 |
|---|---|---|
| 公告 | 事件类型、日期、金额、占营收比、evidence | 事件因子（23） |
| 新闻 | 情绪分、主题、涉及个股 | 情绪因子 |
| 研报 | 评级变化、目标价、关键词 | 分析师因子 |
| 财报文本 | 风险提示、管理层语气 | 质量/风险因子 |

### 8.2 LLM 与 ML 的分工（不能互换）

| | 站 | 干什么 | 用错的后果 |
|---|---|---|---|
| **LLM** | L1 | 文本 → 字段（带 evidence） | 直接打分当信号 → 不可复现、不可审计 |
| **ML** | L2 | 字段 → 排序/概率 | 拿去抽文本 → 贵、慢、不可解释 |

**LLM 负责「看见」，ML 负责「排序」。**

### 8.3 LLM 抽取的三条红线

1. **每个字段必须带原文 evidence**（可审计）
2. **禁止推断**（原文没说的，不许补）
3. **模型和 prompt 版本入库**（可复现）

### 8.4 怎么评估抽取质量

- 手工标 200~500 条，算 precision / recall / F1
- 按事件类型分别看（长尾类型通常很差）
- **最终看策略**：抽取提升 5% 的 F1，策略收益提升了吗？

> 仓库的结论：抽取不是瓶颈，**评估和策略才是**。见 [23 事件驱动系统总览 §11](../参考/事件驱动系统总览.md)。

## 9 因子挖掘自动化：替代了什么，没替代什么

### 9.1 RD-Agent 的循环

```
propose（提假设）→ exp_gen（写表达式）→ coding → running（回测）→ feedback → record
```

对应仓库：[`rd_loop_wrapper.py`](../../backend/services/engine/rd_agent/rd_loop_wrapper.py)。

### 9.2 它替代的三件体力活

1. 人想公式
2. 人写代码
3. 人跑回测

### 9.3 它没替代的三件事

1. **判断经济逻辑**（说不出来源的，直接扔）
2. **判断是不是噪声**（搜得越多，最好的那个越可能是过拟合）
3. **判断能不能过成本**

### 9.4 搜索空间越大，越需要护栏

| 搜了 N 个表达式 | 纯噪声下「最好」的 IC 期望（经验量级） | 对策 |
|---|---|---|
| 100 | ~0.03 | 样本外 |
| 1,000 | ~0.05 | 样本外 + 相关性去重 |
| 10,000 | ~0.07 | 多重检验校正 + 独立 holdout |
| 100,000 | ~0.10 | 基本不可信 |

**护栏清单**：

- [ ] 最后 2 年数据完全不参与搜索（真 holdout）
- [ ] 多重检验校正（Bonferroni / deflated Sharpe）
- [ ] 与已有因子相关 > 0.7 的去重
- [ ] 经济逻辑筛查（人工过一遍）
- [ ] 换手/成本筛查
- [ ] 在另一个市场/板块复现（如沪深 300 → 中证 500）

> **因子挖掘不是「找到更多因子」，是「更快地生成假设，然后用同样严格的标准杀掉它们」。**

## 10 一个最小可跑的流程（40 行）

```python
import pandas as pd, numpy as np, lightgbm as lgb

# 1) 数据：日期 × 股票 的因子矩阵 + 未来收益
X = features                                  # MultiIndex (date, symbol) × 因子列
y = fwd_ret.groupby(level=0).rank(pct=True)   # 按日截面排名，抗极值

# 2) 时间切分 + embargo（训练/验证/测试三段，验证集只用于早停）
dates = X.index.get_level_values(0).unique().sort_values()
split = int(len(dates) * 0.7)
valid_start = int(len(dates) * 0.6)
train_dates = dates[:valid_start - 5]
valid_dates = dates[valid_start:split - 5]
test_dates  = dates[split:]

# 3) 训练（早停用验证集，不用测试集）
model = lgb.LGBMRegressor(
    n_estimators=2000, learning_rate=0.02, num_leaves=31,
    min_data_in_leaf=500, feature_fraction=0.8, bagging_fraction=0.8,
)
model.fit(X.loc[train_dates], y.loc[train_dates],
          eval_set=[(X.loc[valid_dates], y.loc[valid_dates])],
          callbacks=[lgb.early_stopping(100)])

# 4) 预测 → 排序 → 套用 03 的组合流程
score = model.predict(X.loc[test_dates])

# 5) 评价：IC（不是 MSE）
pred = pd.Series(score, index=X.loc[test_dates].index)
real = fwd_ret.loc[test_dates]
ic = (pd.DataFrame({"pred": pred, "real": real})
        .groupby(level=0)
        .apply(lambda d: d["pred"].corr(d["real"], method="spearman")))
print(ic.mean(), ic.mean() / ic.std())
```

**预期结果**：OOS IC 比规则版高 0~0.01。**如果没有提升，说明特征里没有新信息，换模型没用。**

## 11 什么时候值得上深度学习

满足以下**全部**三条才考虑：

1. 规则策略和树模型都已跑通，且能诊断过拟合
2. 有一个树模型吃不下的问题（分钟级、订单簿、多市场、大文本）
3. 有足够的数据和算力（不是「我想学」）

**日频 A 股选股，DL 大概率是负资产**：多花 10 倍时间，换来更差的样本外。
详见 [ML 要不要学 §4](../参考/ML要不要学.md)。
