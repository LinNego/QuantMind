## 0 先改一个认知：量化研究本身就是 Agent 任务

很多人把「学 Agent」和「学量化」当成两件事，于是两边都学不深。
其实量化研究天然具备 Agent 训练需要的全部要素：

| Agent 能力 | 量化里的对应物 | 为什么真实 |
|---|---|---|
| **工具调用** | duckdb 查 parquet、跑回测、读字段 | 工具会超时、返回脏数据、单位错 |
| **上下文工程** | 字段字典、陷阱清单、实验日志 | 信息量大，必须选择性注入 |
| **状态与恢复** | 长跑回测、批量推理 | 进程会挂，必须能续跑 |
| **评测** | IC、分层、样本外、安慰剂 | **有 ground truth（未来收益）** |
| **多智能体** | 多空辩论、代码审查 | 有对抗性，能暴露分歧 |
| **安全边界** | 不许自动下单、不许承诺收益 | 真实约束，不是玩具 |

> **结论：你用「做量化」来练 Agent，比刷 10 个 Agent 教程更接近真实工作。**
> 因为真实工作里，工具就是脏的、评测就是难的、结论就是不确定的。

## 2 三个融合项目（作品集的主体）

### 项目 1：因子研究 Agent（工具 + 记忆 + 评测）

**目标**：输入一个因子表达式，自动产出「IC / 分层 / 换手 / 相关性 / 成本后」检验表。

| 要素 | 设计 |
|---|---|
| **工具** | `query(table, fields, where)`、`compute_ic(factor, label)`、`layer_returns(factor, n)`、`check_leakage(expr)` |
| **状态** | 读写 [因子台账](02-因子研究.md#7-因子台账你的核心资产)（JSON 或 Markdown 表） |
| **评测** | 用 02 的 5 个因子当金标准；Agent 算的 IC 与你手算差 < 0.005 |
| **失败模式** | 幻觉字段名、单位错、用了 `future_return_*`、样本外偷看 |
| **产出** | `scripts/learning/agent_factor/` + 一份《它错在哪》报告 |

**关键**：不要让它「判断因子好不好」。让它**产出证据**，判断由你做。
这就是「Agent 负责看见，你负责签字」。

### 项目 2：公告事件抽取 Agent（LLM + 证据链）

**目标**：公告文本 → 结构化事件（类型 / 日期 / 代码 / 强度 / evidence）。

| 要素 | 设计 |
|---|---|
| **输入** | 东财公告或 `data/regulatory/events.parquet` |
| **输出** | JSON：`{type, symbol, event_date, magnitude, evidence}` |
| **评测** | 手工标 200 条，算 precision / recall / F1，按事件类型分开看 |
| **红线** | `evidence` 必填、禁止推断、prompt + 模型版本入库 |
| **产出** | 事件表 + 抽取报告 + 「抽取提升是否转化为策略收益」对比 |

**参考**：[scripts/events/01](../../scripts/events/01_build_event_library.py)、
[02](../../scripts/events/02_event_study.py)、[23 事件驱动](../参考/事件驱动系统总览.md)。

> 这个项目能同时证明两件事：你会用 LLM 做结构化，且你知道**抽取不等于 alpha**。

### 项目 3：多空辩论 Agent（multi-agent）

**目标**：给定一只股票，多头 / 空头 / 裁判三个角色，输出**可追溯的分歧清单**。

| 要素 | 设计 |
|---|---|
| **角色** | 多头（找证据）、空头（找反例）、裁判（只列分歧，不下结论） |
| **评测** | 人工 0–3 分；结论与后续 20 日收益的相关性只作参考（样本太小） |
| **关键** | 价值不是「更准」，是**暴露分歧和证据缺口** |
| **产出** | 一份辩论记录 + 你的独立判断 |

**参考**：`skills/stock-research`、`skills/stock-deep-research` 的多 Agent 思路。

> 面试官对「多 Agent 选股」的兴趣，远低于对「你怎么知道它错了」的兴趣。

## 3 每周循环（Agent 版）

| 时间 | 做什么 | 谁做 |
|---|---|---|
| 周日 | 定一个**可证伪**的问题 + 写验收标准 | 你 |
| 周一–周三 | 写规格（输入/输出/判据）→ Agent 写代码 | 你 + Agent |
| 周四 | 跑实验，记录数字到 `scripts/learning/LOG.md` | 你 |
| 周五 | Agent 按题库出 3 题，你答；Agent 判卷，你复核 | Agent + 你 |
| 周六 | 更新因子台账 / 策略卡片 / 死法清单 | 你 |

**三条规矩**：

1. **Agent 不写结论，只写证据。** 结论必须你自己下。
2. **先预测，再跑数。** 跑之前写下「我预计 IC 多少」，跑完对比——这是校准判断力的唯一方法。
3. **每个数字都要能复现。** 命令、参数、数据版本，缺一不可。

## 4 评测：怎么知道你（和 Agent）在进步

### 4.1 题库

[评测题库](评测题库.md)：24 条，覆盖 01–06，0–3 分制。

### 4.2 基线

| 时间 | 你 | Agent | 说明 |
|---|---|---|---|
| 第 1 周 | 自测一遍，记分 | 同一套题 | 基线 |
| 第 4 周 | 重测 | 重测 | 看提升 |
| 第 8 周 | 重测 | 重测 | 应该 > 基线 30% |
| 第 12 周 | 重测 | 重测 | 判断类题你应该超过 Agent |

### 4.3 目标不是「Agent 满分」

| 题型 | 期望 |
|---|---|
| 检索/计算（字段单位、公式） | Agent 应该接近满分，你也要满分 |
| 判断/取舍（这个因子该不该杀） | **你应该超过 Agent** |
| 失败诊断（回测为什么假） | 你先答，Agent 补充；看谁先想到 |

**如果你的判断类分数一直低于 Agent，说明你在偷懒——把签字权交出去了。**

## 6 一句话

> **这 16 周不是「学两个东西」，是「用一个有 ground truth 的真实领域，练另一种工程能力」。**
>
> 量化提供「对错」，Agent 提供「杠杆」。你提供「定义问题 + 签字」。
