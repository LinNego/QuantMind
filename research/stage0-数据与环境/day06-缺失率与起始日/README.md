# D06 · 缺失率与起始日

> 阶段 0 · 数据与环境 ｜ 第 6 天 ｜ 状态：✅ 已完成

## 今天要干嘛

知道**哪一列在哪段时间能用**——不是只看缺失率，还要看「第一份非空日期」。

## 要看懂什么

- [quantdb-fields/SKILL.md](../../../skills/quantdb-fields/SKILL.md) 第 1、6 节（单位规则 + `features_daily` 列说明）

## 具体做法

对 `features_daily` 的每一列算两件事：

1. 缺失率
2. **这一列第一份非空数据的日期** ← 这一步才是重点

```bash
python research/stage0-数据与环境/day06-缺失率与起始日/code.py
```

## 完成判据

能回答「`pe_ttm` 从哪一年才有？」以及「2026 年新增的那批列，2016 年为什么全空」。

## 当天总结

79 列 / 10,550,057 行。三类：

| 类 | 数量 | 起始日 | 怎么办 |
|---|---|---|---|
| 完全没缺 | **16** | 2016-01-04 | 随便用 |
| 2026 年才开始 | **21** | **2026-01-05** | 历史全空是**正常**，做 2016–2024 回测**根本不能用** |
| 中途才开始 | **6** | **2017-01-16** | `pe_ttm`/`pe_static`/`ps_ttm`/`net_profit_ttm`/`revenue_ttm`/`annual_net_profit` |

**结论：阶段 1 的 `1/pe_ttm` 策略最早只能从 2017-01-16 起跑。**

另外两个暗坑记在 [D10](../day10-两个暗坑/README.md)：6 个 `future_return_*` 泄漏列、29 个 VARCHAR 数值列。

**为什么必须算「起始日」**：只看缺失率 90% 会以为数据坏了，看了起始日才知道那是**新增列**。
这两者的区别，决定了你该补数据还是该改策略。
