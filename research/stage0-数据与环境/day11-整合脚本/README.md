## 今天要干嘛

听懂一份完整的体检脚本在做什么，并能让它跑出自己的报告。

## 要看懂什么

- 打开本目录的 [full_check.py](full_check.py)，**只读不算**——它是参考实现，不是作业答案

## 具体做法

```bash
python research/stage0-数据与环境/day11-整合脚本/full_check.py
```

它会一次跑完 D01–D10 的全部检查，输出一份完整报告。

**先读代码，再跑。** 重点看它每一段用的是哪条 SQL、哪一列。

## 完成判据

能指着 `full_check.py` 的任意一段，说出它在查什么、为什么这么查。

## 当天总结

跑一次 `full_check.py`，9 个章节一次出完，覆盖 D02–D10 的全部结论：

| 报告章节 | 对应哪天 | 结论 |
|---|---|---|
| 1 规模 | D02 | 2,623 交易日 / 5,581 只 / 1,082 万行 |
| 2 每年股票数 | D03 | 2,632 → 5,577，单调上升 |
| 3 字段缺失率 | D06 | 12 列缺失 90.5%，**全部是 2026-01-05 新增** |
| 4 价格量异常 | D04 | `volume ≤ 0` 254 条，其余全 0 |
| 5 涨跌幅超档 | D05 | 贴档正常，超档全是新股前 3 日 |
| 6 幸存者偏差 | D09 | **十年退市 0 只** |
| 7 单位自检 | D07 | `close×volume/amount` ≈ 10,000 |
| 8 暗坑自检 | D10 | 6 个泄漏列 + 29 个字符串数值列 |
| 9 覆盖缺口 | D05/D13 | `features_daily` 缺北交所 353 只 |

**这一步真正的价值不是「多一份报告」，是发现单点脚本各自为政时会互相矛盾。**

实际例子：D05 我一开始用**不复权价**算涨跌幅，得到 5,223 条「超档」；
换成前复权后只剩 335 条，再剔除停牌复牌首日剩 294 条。
而 `full_check.py` 用 `features_daily.zaf`，只有 8 条。

同一个问题、四套口径、四个答案。**这就是为什么必须有一个统一的检验脚本。**
