```bash

qd      # 进仓库 + 开 DuckDB（23 张表已建视图，直接 SELECT）
```

DuckDB 里的短名（定义在 `qdb.sql` 末尾）：

| 短名 | 表 |
|---|---|
| `ku` / `kf` / `kb` | 不复权 / 前复权 / 后复权 日线 |
| `feat` | `features_daily`（79 列宽表） |
| `val` / `ti` / `idx` | 估值 / 技术指标 / 指数 |

脚本统一用 `os.getenv("QM_QUANTDB_DATA_DIR", "/opt/quantmind/data/quantdb")`，换机器只改环境变量。

**不许进 git**：`*.parquet` / `*.pkl` / `*.h5`、复制粘贴的完整数据集、别人的策略代码。
一次性的临时探测放 `scratch/`（已 gitignore）。

## 每天的时间线

| 时段 | 干什么 |
|---|---|
| 白天 45 分钟 | 读当天 day 页「要看懂什么」里的链接 |
| 白天 10 分钟 | 写**开工卡**（下面 3 行） |
| 白天 5 分钟 | 记问题清单，晚上一次性问，**别边写边查** |
| 晚上 2 分钟 | `git pull`（同步另一台机器的进展） |
| 晚上 60 分钟 | 按 day 页「具体做法」做，30 分钟内必须跑出一次结果 |
| 晚上 5 分钟 | 三行日志：今天跑出了什么 / 卡在哪 / 明天第一件事 |

**开工卡 3 行：**

```
今晚写：def rank_ic(factor_df, fwd_ret) -> pd.Series

判据：每天截面算 Spearman，再对时间求均值，输出一个数
```

**白天不要做三件事**：刷视频教程、在工作电脑上配环境、提前写代码。

## 分工（D13 起变了）

| 事 | 谁做 | 为什么 |
|---|---|---|
| 写代码 | **AI** | 它比你快、比你少打错字 |
| 写规格 | **你** | 说不清楚 → AI 一定实现错，而且错得理直气壮 |
| 判断对不对 | **你** | AI 没法判断自己错没错 |
| 决定做不做 | **你** | 只有你知道自己能承受多大回撤 |

**可以放弃**：记住 pandas API、自己写回测循环、调参画图、装环境。
**不能放弃**：看懂 `w.shift(1) * ret`、知道 5 个验收问题怎么查、判断「这结果好得不像真的」、样本外只跑一次的纪律。

> **你不写代码，但你签字。签字前必须走完 5 问。**

5 问见 [参考/验收清单.md](参考/验收清单.md)。

## 三条硬规矩

1. **Gate 过不了不许往下走。** 前面的错会以「结果还不错」的形式藏到后面。
2. **样本外只跑一次。** 跑第二次，它就变成样本内了。
3. **每天三行日志。** 半年后你必须能复现任何一次实验。

## 时间不够时怎么砍

| 情况 | 怎么砍 |
|---|---|
| 只有 **1 小时/天** | 阶段 0 保持 12 天不变（**不能砍**），阶段 1 拉到 4 周，阶段 2 只做 3 个因子，阶段 3 跳过行业中性，**阶段 4 直接跳过** |
| 某周出差 / 加班 | **不许跳过格子**，只许顺延。跳一个格子，后面两格会白做 |
| 卡在某一格超过 3 天 | 停下来，把「卡在哪」写清楚来问，别硬耗 |

**可以砍的**：ML、行业中性、IC 加权、WFA。
**不能砍的**：成本三档、T+1、样本外只跑一次、实验日志。
