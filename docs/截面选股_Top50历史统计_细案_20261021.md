# 截面选股 · 单模型 Top-K 历史选股统计 · 实施细案（2026-10-21）

> 需求原文：「那个截面选股，也做一个选股 top50 的选股能力基于测试数据集、也和组合选股一样可以统计的、能做吗。按模型训练的周期换股，或者滚动选股 top50。统计历史数据。」

## 1. 目标

在「推理中心 → 截面选股」内新增**历史统计**视图：对**单个模型**，用 `pred.parquet` 的
`split='test'` 截面排名，按两种换股方式做历史组合模拟，统计收益、超额、回撤、胜率、
逐月拆解与逐期明细。收益口径与组合选股「周期收益」一致：**收盘价、无手续费、无印花税、
无滑点、无冲击成本**，用于衡量**排序能力**，不是可交易收益预测。

两种模式（用户指定）：

| 模式 | 换股方式 | 持有期 |
|---|---|---|
| 周期换股 | 每 H 个交易日换一期，期与期首尾相接（同一收盘价交接） | H = 模型 `target_horizon_days`（缺省 10） |
| 每日滚动 | 每个交易日换一期 | 1 个交易日 |

## 2. 已核实的现状（2026-10-21 实测）

### 2.1 数据事实

以 `mdl_cn_train_20261019002855_08734e9b_ccf614f8`（CN / tabnet / T+10）为例：

| 项 | 实测 |
|---|---|
| `split='test'` | 2,125,270 行，414 个交易日，2025-02-05 ~ 2026-10-19 |
| 每日可选标的 | 5,001 ~ 5,212 只 |
| Top50 并集 | 3,088 只 |
| 入场价缺失 | 4 / 20,700（0.02%） |
| 退出价缺失 | 59 / 20,700（0.29%，含最后一期未到期） |
| Top50 抽取耗时 | 0.21 s（DuckDB 窗口函数） |
| 全区间收盘价读取 | 1.0 s / 1.27M 行 / 176 MB（可列裁剪到约 60 MB） |
| 端到端预估 | **约 2 s**（含基准），预算 60 s |
| 样本结果（无费用） | 每日滚动 +91.24%（期均 +0.168%，期胜率 60.1%，最大回撤 -17.22%）；H=10 周期 +51.31%；H=20 周期 +50.79%；沪深300 同期 +8.05% |

以上最后一行只作为**实现后的冒烟对照**，入测试时容许因数据更新产生小幅漂移。

### 2.2 代码现状

- 仓库中**没有**单模型 + test split + TopK + 持有期收益的 API/service；只有：
  - 组合选股 `model_blend_service.period()`（多模型、固定资金槽位、不复利）；
  - 脚本 `skills/batch-inference-analysis/scripts/top20_model_eval.py`（Top20、单文件脚本、含费用）；
  - 评估脚本 `backend/scripts/eval/realized_stats.py`（IC/分组/换手，无收益组合）。
- 可复用：`model_registry.resolve_effective_model`、`QuantDBDataHub.fetch_daily_kline_batch`
  / `fetch_index_kline`、`period_performance` 的格式约定、前端 `buildEquityGeometry`。
- **不能复用 `simulate_period`**：它的每笔预算固定为 `capital/positions`，盈利留作现金，
  不是满仓复利；本需求每期把当期全部权益等权投入，必须新写纯函数。

## 3. 关键口径（钉死）

1. **信号日 T**：`pred.parquet` 中 `split='test'` 且有有效 `pred` 的交易日。
2. **入选**：每个信号日按 `pred` 降序取前 K 名，`symbol` 升序做稳定 tie-break；K ∈ [1, 50]。
   **不做 ST/退市过滤**（当前 ST 标记是静态截面，用于历史即前视），也不做涨跌停/停牌可交易性
   过滤（`params.tradability = "not_modeled"` 明示）。
3. **入选日（执行滞后）**：`entry = 信号日之后第 execution_lag_days 个交易日`（默认 1，读
   metadata `execution_lag_days`）。收盘价成交。
4. **退出日**：`exit = entry 之后第 hold_days 个交易日`（入选日不算一天）。
5. **价格**：QuantDB `daily_forward`（**前复权 / qfq**）收盘价。为什么不用 `label_return`：
   训练标签按 `daily_backward`（hfq）构造，而 `daily_backward` 是跨分区拼接的坏序列
   （2026-09-23 铁证：无除权日平滑漂移、累计因子可下降、单票符号翻转），
   且部分模型（如 10000001 的 CN 模型）根本没有 `label_return` 列。
   同日/跨日收益一律用 qfq。
6. **资金**：每期把当前全部权益在有效入选标的中**等权**投入，期收益 = 等权平均收益，
   权益逐期复利。初始资金只做金额缩放，不影响百分比结果。
7. **缺失价格**：
   - 入选日缺价 → 该标的从本期剔除（`missing_entry_price`），不拿旧价假装成交；
   - 退出日缺价 → 用 `(entry, exit]` 内最后一个有效收盘价退出（`stale_exit`）；
     窗口内全无价 → 剔除（`missing_exit_price`）；
   - 本期有效标的为 0 → 跳过本期，权益不变（`skipped_cohorts`）；
   - **任何缺失绝不写 0**，展示面一律 `—`。
8. **未到期期**：退出日超出行情末日 → 按行情末日（或该票最后一个有效收盘价）估值，
   `open=true`，计入总收益与月度，并在告警与明细状态中标注。
9. **基准**：沪深300（`000300.SH`，QuantDB `index_daily`），按**同一期窗**收盘到收盘
   计算并复利；指数缺价 → 该期基准为 `null`、超额 `null`，不猜 0。
10. **期与期交接**：下一期入选日 = 上一期退出日（同收盘价卖出/买入），期收益可直接连乘，
    不产生空档或重叠。

## 4. 组合模拟（纯函数）

新文件 `backend/services/engine/inference/selection_stats.py`，无 IO。

```python
def simulate_selection(
    *,
    calendar: Sequence[date],                  # 交易日升序（行情/指数日期并集）
    signal_days: Sequence[date],               # 区间内有效信号日升序
    picks_by_signal: Mapping[date, Sequence[str]],  # 信号日 → TopK（已排序）
    closes: Mapping[str, Mapping[date, float]],      # 标的 → {日期: qfq 收盘}
    benchmark_closes: Mapping[date, float] | None,
    top_k: int,
    hold_days: int,
    execution_lag_days: int = 1,
) -> dict
```

返回（**单位资金，equity 为倍数**，service 层乘 capital）：

- `summary`: `total_return_pct / max_drawdown_pct / benchmark_return_pct / excess_return_pct /
  cohorts / closed_cohorts / open_cohorts / win_cohorts / loss_cohorts / cohort_win_rate_pct /
  avg_cohort_return_pct / median_cohort_return_pct / picks / priced_picks /
  pick_win_rate_pct / avg_pick_return_pct / price_coverage_pct / data_quality`
- `months`: `month / start_date / end_date / start_equity / end_equity / return_pct /
  profit_amount（单位资金下为倍数差）/ cohorts / win_rate_pct / benchmark_return_pct /
  excess_return_pct / partial`
- `cohorts`: `index / signal_date / entry_date / exit_date / exit_kind(closed|open) /
  requested_top_k / held / priced / missing_entry / missing_exit / stale_exit /
  return_pct / benchmark_return_pct / excess_return_pct / equity / partial`
- `points`: `[{date, equity}]`，首点 = 首期入选日 / 权益 1，之后每期一个点（退出日或估值日）
- `warnings`: 计数与标记（见 §7）

期起点选择：按有效信号日升序遍历，仅当 `entry_index >= 上一期 exit_index` 时接受为新一期
（首期直接接受）。这样 H=10 的干净测试集恰好每 10 个信号日一期；遇评分缺口自动顺延，
保证期与期不重叠。

## 5. API

`GET /api/v1/models/{model_id}/selection-stats`（JWT，`(tenant_id,user_id)` 隔离）

| 参数 | 类型 | 默认 | 约束 |
|---|---|---|---|
| `start` | YYYY-MM-DD | 测试集首日 | 与 `end` 同时给 |
| `end` | YYYY-MM-DD | 测试集末日 | |
| `top_k` | int | 50 | 1..50 |
| `hold_days` | int | 模型 H | 1..60（1 = 每日滚动） |
| `capital` | float | 10,000,000 | >0, ≤1e12 |

响应（节选）：

```json
{
  "model_id": "...",
  "model_name": "...",
  "market": "CN",
  "split": "test",
  "requested": {"start": "...", "end": "...", "top_k": 50, "hold_days": 10, "capital": 10000000},
  "effective": {"start": "...", "end": "...", "first_signal_day": "...", "last_signal_day": "...",
                "first_entry_day": "...", "last_exit_day": "...", "trading_days": 414, "signal_days": 413},
  "params": {"horizon_days": 10, "execution_lag_days": 1, "entry_convention": "close",
             "exit_convention": "close", "price_adjust": "qfq", "fee_convention": "none",
             "tradability": "not_modeled", "benchmark": "000300.SH"},
  "summary": {...},
  "months": [...],
  "cohorts": [...],
  "points": [...],
  "warnings": ["effective_start_clamped", "..."]
}
```

服务层 `backend/services/engine/services/model_selection_stats_service.py`：

- 解析模型：`resolve_effective_model(tenant, user, model_id, market="CN")`；
  显式模型未命中（`fallback_used`）→ 404；市场非 CN → 422 `unsupported_market`。
- 读 `metadata.json`：`target_horizon_days`（缺省 `horizon_days`，再缺省 10）、
  `execution_lag_days`（缺省 1）。
- 定位 `pred.parquet`：`storage_path/pred.parquet`，再 `pred/pred.parquet`（与
  `model_backfill.resolve_pred_candidates` 同口径）。
- DuckDB 抽取 TopK：`split='test' AND pred IS NOT NULL`，窗口
  `row_number() OVER (PARTITION BY trade_date ORDER BY pred DESC, symbol)`；
  同时返回每日 `scored` 数量。列投影只取 `symbol/trade_date/pred`。
- 收盘价：新增 `QuantDBDataHub.fetch_daily_close_batch(symbols, start, end, adjust="qfq")`
  （列裁剪 `symbol/close/time`，走既有 `_read_partitioned`）；pandas `pivot` 成
  `symbol × date` 矩阵，只保留入选并集。
- 基准：`fetch_index_kline("000300.SH", ...)`；失败 → `benchmark_unavailable` 告警，
  基准与超额为 `null`。
- 缓存：进程内 LRU（8 条，TTL 300 s），键 = `model_id + pred mtime + start/end/top_k/hold_days/lag`；
  **不含 capital**（单位资金缓存，响应时缩放）。
- 错误（`SelectionStatsError` → `detail={code,message}`）：
  `pred_unavailable` / `split_unavailable` / `insufficient_signal_days` /
  `quote_source_unavailable` / `unsupported_market` / `model_unavailable`。

路由文件 `backend/services/api/routers/model_selection_stats.py`，在 `main.py` 中**先于**
`model_training_router` 注册（两段路径本不会被 `GET /{model_id}` 遮蔽，前置注册是防御）。

## 7. 告警码

| 码 | 含义 |
|---|---|
| `effective_start_clamped` / `effective_end_clamped` | 请求区间被夹到可用信号日 |
| `short_window` | 有效信号日 < 20，统计意义有限 |
| `underfill_signals` | 部分信号日可选标的 < top_k |
| `missing_entry_price` | 入选日缺价，标的剔除 |
| `missing_exit_price` | 退出日及窗口内均缺价，标的剔除 |
| `stale_exit` | 退出日缺价，用窗口内最后有效收盘价 |
| `partial_cohorts` | 单期有效标的 < 请求数的 80% |
| `skipped_cohorts` | 单期有效标的为 0，整期跳过 |
| `open_cohort` | 末期未到期，按行情末日估值 |
| `benchmark_unavailable` | 基准行情不可用，基准/超额为 null |
| `calendar_from_prices` | 指数日历不可用，交易日取自入选标的收盘价并集 |

## 10. 测试计划（TDD：RED → GREEN）

纯函数 `test_selection_stats.py`：

1. 单期两名等权，收益/权益/月度与手算一致；
2. H=2 非重叠期起点、入选日/退出日精确，逐期复利正确；

9. 任何缺失不写 0；空 picks 不崩；

## 11. 淘汰判据（Kill Criteria）

- **K1 数据充分性**：模型无 `pred.parquet`、无 `split='test'`、或有效信号日 < 5 →
  不做降级猜测，API 返回 422，前端显示不可用原因。
- **K2 价格可信**：入选并集收盘价覆盖率 < 90% → 422 `quote_source_unavailable`，
  绝不用 0 价或标签收益顶替。
- **K3 口径自洽**：金样手算（3 标的 × 2 期）与实际差 > 1e-6，或真实模型首期收益与
  直接价格算术差 > 1e-6 → 停止实现，回查日期/复权/权重。
- **K4 性能**：全测试集（≥ 400 信号日）首屏 > 60 s 或响应 > 20 MB → 改为只返回聚合
  （去掉逐期明细）后再评估；仍超则不做该视图。
- **K5 展示合规**：面板与源码扫描出现「买/卖/加仓/减仓/建仓/清仓」任一字眼 → 不得合入。
- **K6 统计误导**：若把无费用结果展示成可实现收益（缺少「不含费用/滑点」脚注或
  `tradability_not_modeled` 未明示）→ 不得合入。

## 13. 明确不做

- 不做手续费/印花税/滑点/冲击成本（用户明确要求）；
- 不做涨跌停、停牌、ST、退市可交易性过滤（`tradability_not_modeled` 明示）；
- 不做全候选池等权基准（本期用沪深300；候选池等权作为后续增强）；
- 不做逐期持仓名单明细（414 期 × 50 只 ≈ 2 万行，接口体积不可控；当期名单看「当日截面」）；
- 不支持 HK/US/CRYPTO/FUTURES（数据源与复权口径不同，先做 CN）；
- 不写任何订单/委托/成交语义，仅纸面统计。
