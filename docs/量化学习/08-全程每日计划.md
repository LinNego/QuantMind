# 08 · 全程每日计划（阶段 0 → 阶段 5）

> **每天 2 小时**：白天挤 1 小时（读） + 晚上 1 小时。
> **D01–D12 晚上自己动手；D13 起改成「AI 写代码 + 你写规格并验收」**（见 [0.6](#06-分工变了ai-写代码你写规格--验收)）。
> 每周 6 个学习日 + 1 天缓冲。**一个学习日 = 一个格子，做完打勾，做不完第二天接着做，不许跳。**

## 0.5 白天那 1 小时到底干什么

**白天不写代码、不跑数据。** 白天只干一件事：**把晚上那 1 小时从「查资料 + 试错」压缩成「只写代码」。**

原因很实际——晚上 1 小时最贵，最容易被三件事吃掉：找文件、查参数、试错报错。这些活儿白天刷手机、开 IDE 都能干，晚上干就是浪费。

### 三段：45 + 10 + 5

| 时长 | 干什么 | 产出 |
|---|---|---|
| **45 分钟** | 读当天格子里「白天 1h」那一列指定的文档章节或源码 | 概念进脑子 |
| **10 分钟** | 写**今晚开工卡**（就下面 3 行） | 晚上直接动手 |
| **5 分钟** | 把不懂的记成问题清单，晚上一次性问，**别边写边查** | 问题列表 |

### 开工卡（3 行，抄在备忘录里就行）

```
今晚写：def rank_ic(factor_df, fwd_ret) -> pd.Series
输入：日期×股票 的两个矩阵
判据：每天截面算 Spearman，再对时间求均值，输出一个数
```

有了这 3 行，晚上坐下就能写，不用再想「我该写什么」。

### 工作电脑上能干什么 / 不能干什么

| 能做 | 不能做 |
|---|---|
| `git clone` 仓库，用 IDE 本地读代码（比网页舒服） | 装 11 GB 数据跑回测 |
| 读文档、读 `.py`、看 commit | 跑 `00_data_check.py`（没数据） |
| 手抄数据字典、画表结构 | 折腾 DuckDB 环境 |
| 把开工卡写进备忘录 | —— |

**代码随手 clone，数据不用跟着走。** 白天只「读」，晚上回有数据的那台机器「写」。

### 白天不要做的三件事（最耗时且无效）

1. ❌ **刷视频教程** —— 看完觉得懂了，晚上一行写不出。要读就读这个仓库的文件，它是你唯一要搞懂的系统。
2. ❌ **在工作电脑上配环境** —— 装 Python、搞 DuckDB、下数据，能吃掉三天。
3. ❌ **提前写代码** —— 白天写的晚上大概率推翻重写，因为读的东西还没消化完。

### 一天完整时间线

```
白天 45 分钟   读 08 今天那一格的「白天 1h」
白天 10 分钟   写开工卡（函数签名 + 输入输出 + 判据）
白天  5 分钟   记问题清单

晚上  2 分钟   git pull（同步另一台机器的进展）
晚上 10 分钟   照着开工卡写骨架
晚上 30 分钟   必须跑出一次结果（跑不出就缩小范围）
晚上 15 分钟   结果落 research/out/，存表或截图
晚上  5 分钟   写三行日志
```

> `git pull` 放晚上开工前 2 分钟，专治「打开发现代码是旧的那台机器的」。
> **数据不用 pull** —— 数据只在那台常开的机器上，脚本通过 `QM_QUANTDB_DATA_DIR` 找它。

## 0.6 分工变了：AI 写代码，你写规格 + 验收

从 **D13（阶段 1）** 开始，工作方式改成这样：

```
白天 45 分钟   读概念 + 想「这个策略到底怎么定义」
白天 10 分钟   写【策略规格】（[10-验收清单](10-验收清单.md) 附录模板）
白天  5 分钟   把规格发给 AI

晚上 10 分钟   拿到代码，先不看结果
晚上 30 分钟   跑 [10-验收清单](10-验收清单.md) 的 5 问
晚上 15 分钟   5 问全过 → 才允许看净值；有一项没过 → 打回重做
晚上  5 分钟   填【验收记录表】，写进实验日志
```

### 为什么这么改

| 事 | 谁做 | 为什么 |
|---|---|---|
| 写代码 | **AI** | 它比你快、比你少打错字 |
| 写规格 | **你** | 说不清楚 → AI 一定实现错，而且错得理直气壮 |
| 判断对不对 | **你** | AI 没法判断自己错没错 |
| 决定做不做 | **你** | 只有你知道自己能承受多大回撤 |

### 你能放弃的 / 不能放弃的

| 可以放弃 | 不能放弃 |
|---|---|
| 记住 pandas API | 看懂 `w.shift(1) * ret` 在干什么 |
| 自己写回测循环 | 知道 5 个验收问题各自怎么查 |
| 调参数、画图 | 判断「这个结果好得不像真的」 |
| 装环境、修依赖 | 样本外只跑一次的纪律 |

### 一句话

> **你不写代码，但你签字。签字前必须走完 5 问。**

## 4. 三个不许破的规矩

1. **Gate 过不了不许往下走。** 前面的错会以「结果还不错」的形式藏到后面。
2. **样本外只跑一次。** 跑第二次，它就变成样本内了。
3. **每天三行日志。** 半年后你必须能复现任何一次实验，否则会在同一个坑上反复踩，而且不记得踩过。

> 前 12 周你学的是「怎么不被自己骗」，第 13 周才开始学「怎么用机器学习」。
> 顺序反过来，你会浪费三个月。
