## 第 1 天：看见数据

**今日目标**：能把 parquet 读成一张表，并打印出前 5 行。

| 时段 | 做什么 |
|---|---|
| 白天 1h | 读 [01-数据获取与迁移.md](01-数据获取与迁移.md) 第 3 节（L0/L1/L2 三档），知道自己在用哪档 |
| 晚上 1h | 跑下面这段，**改数字玩**（换日期、换股票、换列），直到不靠抄也能写出来 |

```bash
python - <<'EOF'
import duckdb
con = duckdb.connect()
con.execute("SET enable_progress_bar=false")
df = con.execute("""
    SELECT symbol, dt, open, high, low, close, volume, amount
    FROM read_parquet('/opt/quantmind/data/quantdb/1_kline_data/daily_unadjusted/*/data.parquet',
                      hive_partitioning = true)
    WHERE dt = 20261023
    LIMIT 5
""").df()
print(df.to_string(index=False))
print("行数:", len(df))
EOF
```

**完成标志**：终端里打出 5 行真实股票数据，你**能指着每一列说出它是什么**。

**卡住怎么办**：报 `No files found` → 路径里的 `dt=` 目录不存在，先 `ls /opt/quantmind/data/quantdb/1_kline_data/daily_unadjusted | tail` 看最新是哪天。

## 第 2 天：数据有多大、多全

**今日目标**：说清「多少只股票、多少交易日、时间范围、每天股票数怎么变」。

| 时段 | 做什么 |
|---|---|
| 白天 1h | 读 [quantdb_datasets.py](../..//backend/shared/quantdb_datasets.py) 里的 `DatasetSpec` 列表（29 个），只看名字和备注 |
| 晚上 1h | 把第 1 天的脚本改成三个统计：`count(DISTINCT symbol)` / `count(DISTINCT dt)` / `min(dt), max(dt)` |

```python
# 提示：一条 SQL 就能全拿到
SELECT count(DISTINCT symbol) AS 股票数, count(DISTINCT dt) AS 交易日数,
       min(dt) AS 起, max(dt) AS 止, count(*) AS 总行数
FROM read_parquet('.../daily_unadjusted/*/data.parquet', hive_partitioning = true)
```

再算「每年最后一个交易日的股票数」——你会看到 2 千多涨到 5 千多。

**完成标志**：能不看屏幕说出「我的数据是 X 只股票、Y 个交易日、从 A 到 B」，并且知道**股票数是逐年增长的**（不是恒定 5000）。

**为什么重要**：如果某天突然只有 500 只股票，你的截面排名当天就是垃圾——这类问题只有这种统计能发现。

## 第 3 天：找脏数据

**今日目标**：找出「不可能存在」的行。

| 时段 | 做什么 |
|---|---|
| 白天 1h | 读 [03-常见陷阱](03-常见陷阱与自检红线.md) 第 6 节（静默降级），理解为什么**不能靠看净值曲线发现问题** |
| 晚上 1h | 写检查：收盘价 ≤ 0、成交量 ≤ 0、最高价 < 最低价、单日涨跌幅超档 |

涨跌幅**按板块分档**，别用一刀切：

| 板块 | 档位 |
|---|---|
| 主板（60/00） | ±10% |
| 创业板（30）/ 科创板（68） | ±20% |
| 北交所（43/83/87/88/92） | ±30% |

**完成标志**：得到一张「异常条数」表，并且**能解释每一条是不是真异常**。

> 提示：你会看到某只创业板新股连续多天涨跌幅 401%——那是新股首日无涨跌幅限制、基准价用了发行价导致的，不是数据坏了，但你必须把它从因子计算里剔掉。

**今日目标**：知道**哪一列在哪段时间能用**。

| 时段 | 做什么 |
|---|---|
| 白天 1h | 读 [quantdb-fields/SKILL.md](../../skills/quantdb-fields/SKILL.md) 第 1、6 节（单位规则 + features_daily 列说明） |

**完成标志**：你能回答「`pe_ttm` 从哪一年才有？」（答案是 2017 年，不是 2016 年）以及「2026 年新增的那批列，2016 年为什么全空」。

**为什么必须算「起始日」**：只看缺失率 90% 会以为数据坏了，看了起始日才知道那是**新增列**，历史天然为空。这两者的区别，决定了你该补数据还是该改策略。

## 第 5 天：单位与复权（最容易全盘错的一天）

**今日目标**：能用一行数字证明「我的单位是对的」。

| 时段 | 做什么 |
|---|---|
| 白天 1h | 读 [03](03-常见陷阱与自检红线.md) 第 2 节（未来函数）+ 复权那几行 |
| 晚上 1h | ① 算 `close*volume/amount` 的年度中位数，看是不是 ≈ 10000<br>② 把同一天的 `daily_forward`（前复权）和 `daily_unadjusted`（不复权）并排放，看差多少 |

**完成标志**：
- 你能说出 **volume 是股、amount 是万元**，并知道这个 10000 是哪来的；
- 你能举一只股票，说明它前复权价和不复权价差多少、为什么。

**这条错了的后果**：所有换手率、资金流、成交额类因子会差 1 万倍，而代码**不会报错**。

**今天学到的**：量化里「数据看着很干净」通常不是好消息。
