# 02 · 核心概念速通（软件工程师视角）

> 这份文档解决一件事：**让你在读量化资料时，每个词都知道对应到自己熟悉的什么东西。**
> 不需要金融背景，也不需要机器学习背景。

---

## 0. 最重要的一句话

> **量化不是编程问题，是统计问题。**

你大概会想：「量化 = 写程序预测股票涨跌，我会写代码，所以上手快。」

前半句错了一半，后半句是**陷阱**。

| 环节 | 它是什么 | 你的软件背景帮得上吗 |
|---|---|---|
| 取数、清洗、存储 | 工程活 | ✅ 大量帮助 |
| 算因子、跑回测 | 工程活 | ✅ 大量帮助 |
| **判断「这个结果是不是运气」** | **统计 + 纪律** | ❌ 几乎帮不上，**而且你的工程能力会让你更快地骗自己** |

软件工程里，**能跑通 = 正确**。量化里完全相反：

> **一个跑得飞快、逻辑毫无 bug、曲线漂亮得要死的程序，大概率是错的。**

因为它可能偷偷用了明天的数据（**未来函数**），或者在测试集上调了几百遍（**过拟合**，股市里比 ML 里狠 10 倍）。

**你的真实处境**：工具层你比 95% 的散户强；判断层从零开始，而且要反着自己工程师的本能来。
**你的最大风险不是学不会，是学太快**——三个月后做出一个年化 80% 的回测，实盘然后亏钱。

## 1. 先建立世界观：你赚的钱从哪来

这是小白 100% 会跳过、但最致命的一步。先别写代码，先回答：

> **对面那个人，凭什么愿意把钱输给你？**

量化赚的钱，本质上只有三类：

| 类型 | 说人话 | 例子 |
|---|---|---|
| **风险溢价** | 你承担了别人不愿意承担的风险，所以拿补偿 | 大家怕波动，你专买低波动股票；大家怕跌，你专买跌惨的 |
| **纠正别人犯错** | 市场情绪化，你冷静 | 恐慌抛售时你接、狂热时你走 |
| **提供流动性** | 别人急着成交，你耐心挂单赚差价 | 高频做市（**散户打不过，别碰**） |

**如果你的因子说不出属于哪一类，它就是在数据里瞎挖出来的。**
挖出来的东西，历史越漂亮，未来越惨——因为它没有「为什么」。

**先有故事，再有代码。** 这是从「会写代码」到「懂量化」的分水岭。

## 2. 术语对照表（背下来，后面所有资料都能读）

| 量化词 | 说人话 | 你的软件类比 |
|---|---|---|
| **因子 / 特征 (Factor)** | 一个打分函数：输入一只股票的历史数据，输出一个数，越大越看好 | 一个纯函数 `score(stock) -> float`，或一个 feature |
| **Alpha** | 确实有预测能力的因子 | 通过 A/B 测试的 feature |
| **策略 (Strategy)** | 按分数排序买前 N 名，定期换仓 | 一个服务：输入分数，输出持仓 |
| **回测 (Backtest)** | 假装回到过去，用历史数据每天跑一遍策略，看赚多少 | 用 replay 的历史请求跑 e2e 测试 |
| **IC** | 你的分数排名与「未来实际涨跌」排名的相关性（-1~1） | 预测值和真实值的相关系数 |
| **ICIR** | IC 的均值 ÷ IC 的标准差 | 信噪比 / 稳定性 |
| **分层回测** | 按分数分 5~10 组，看收益是否单调 | 分桶压测，看指标是否随参数单调 |
| **未来函数** | 程序用了「当时还不知道」的数据 | **数据泄漏** |
| **过拟合** | 参数调到历史完美，换个时间段就废 | 在测试集上调参 |
| **最大回撤 (MDD)** | 从最高点跌到最低点的最大幅度 | 最坏情况 p100 延迟 |
| **夏普比率** | 收益 ÷ 波动率 | 单位抖动的有效吞吐 |
| **换手率** | 每次调仓换掉多少仓位 | 每次发布要重建多少缓存 |
| **容量** | 策略最多容纳多少钱而不把自己抬死 | 系统 QPS 上限 |
| **幸存者偏差** | 只用「今天还活着」的股票回测，退市的被自动排除 → 结果虚高 | 只统计成功的请求，忽略 500 |
| **前复权 / 后复权 / 不复权** | 处理除权除息后价格断层的三种口径 | 数据统一口径 / 版本对齐 |

## 3. 数据的两个方向：截面 vs 时序（**最容易搞混**）

### 3.1 定义

数据长这样（行 = 日期，列 = 股票）：

```
                 600036.SH   000001.SZ   300750.SZ   ... (5000 列)
2024-01-02          31.55       9.80        168.0
2024-01-03          32.00       9.85        171.2
2024-01-04          31.70       9.78        166.5
   ...
(2500 行)
```

- **横着切（某一天，所有股票）= 截面（cross-section）**
- **竖着切（某只股票，所有日期）= 时序（time series）**

在 pandas 里可以直接背下来：

```python
px.rank(axis=1, pct=True)     # axis=1 → 横着算 → 截面：今天 5000 只里排第几
px.rolling(20).std()          # axis=0 → 竖着算 → 时序：这只股票自己过去 20 天波动
```

### 3.2 关键纠错：截面跟「模型」没有关系

**截面是数据形状决定的，不是你用不用机器学习决定的。** 三个例子，全都不涉及模型：

**例 1：纯规则策略**

> 「买入全市场 PE 最低的 30 只，每月调仓。」

「最低的 30 只」就是**截面排名**。把「分数」换成 `1/PE` 而已，和模型无关。

**对照仓库里的模板**：`strategy_templates/` 的 60 个模板，`STRATEGY_CONFIG` 里都写着 `"signal": '<PRED>'`——意思是「信号用模型分」。把这一行换成 `1/PE` 或 `-mom20`，**策略类的选股逻辑一个字都不用改，照样跑**。

> 这恰好说明：**「截面排名」发生在策略层，与「分数从哪来」完全解耦。** 分数可以来自模型（`<PRED>`）、可以来自因子公式、也可以来自你手写的一列 Excel。
> 换句话说，模板本身是**规则化的选股逻辑**（涨跌停约束、TopK、换手控制、行业过滤），但它**消费的是模型分**——所以别指望「直接用模板 = 不用训练模型」。

**例 2：算 IC**

```
每天：在这一天的 5000 只股票里，算「因子排名」与「未来收益排名」的相关性 → 一个数
然后：把 2500 个数取平均 → IC 均值
```

**每次算的那一次，都是在一个截面上算的。** IC 天生是截面指标——它衡量「同一天里，分数高的是不是真涨得多」。

**例 3：比较两只股票（最直观）**

> 招行 PE 5.2 倍，茅台 PE 28 倍，谁更便宜？

**没有答案，因为不可比**——银行和白酒的估值中枢本来就不一样。

正确问法：「招行的 PE 在**所有银行股里**处于什么分位？茅台的 PE 在**所有白酒股里**处于什么分位？」

这就是截面比较。**绝对数值几乎永远不可比，只有相对位置可比。** 这解释了为什么量化里到处都是排名、分位数、分组、行业中性。

### 3.3 什么时候用截面，什么时候用时序

| 问题 | 用哪个 | 例子 |
|---|---|---|
| 买**哪个**股票？ | **截面** | 今天 5000 只里谁分数最高 |
| **什么时候**买？ | **时序** | 沪深300 PE 处于自身过去 10 年的 12% 分位 → 便宜 |
| 这股票**超跌**了吗？ | **时序** | 现价 vs 它自己的 20 日均线，偏离 -15% |
| 策略**稳不稳**？ | **时序** | 把每日收益连起来算最大回撤 |

> **一句话：截面回答「买哪个」，时序回答「什么时候买」。**

量化里**选股的活远多于择时**，所以到处都是截面操作——但这不代表它跟模型有关。

## 4. 特征工程是什么

### 4.1 一句话

> **把数据库里的原始数据，变成模型能吃的数字表——这个加工过程叫特征工程。**

### 4.2 用你熟悉的东西类比

你有个 `stock_daily` 表：

```
trade_date   symbol      open    high    low     close    volume
2024-01-02   600036.SH   31.20   31.80   31.10   31.55    41000000
```

要给业务做「股票评分」，你不会把原表丢给算法同事，你会先加工出派生字段：

```
ret_1d       = 今天收盘 / 昨天收盘 - 1        # 昨天涨了多少
mom_20d      = 今天收盘 / 20天前收盘 - 1      # 20 天涨了多少
vol_20d      = 过去20天收益率的标准差          # 最近稳不稳
ma20_dev     = 今天收盘 / 20日均线 - 1        # 离均线多远
turnover     = 成交量 / 流通股本              # 换手率
volume_ratio = 今日成交量 / 过去5日均量        # 量比
```

**这就是特征工程。** 在你那儿叫「宽表 / 指标计算 / 中间层」，在 ML 里叫 feature engineering。

### 4.3 为什么模型不能直接吃原始数据

| 问题 | 说明 | 类比 |
|---|---|---|
| **不可比** | 茅台 1700 元、某 ST 股 2.3 元，模型以为茅台「强 700 倍」 | 一个耗时返回秒、一个返回毫秒 |
| **全局噪声** | 指数从 3000 涨到 3200，所有股票价格全涨，但公司没变好 | 全局变量污染，必须归一化 |
| **太原始** | 「成交量 4100 万」本身没意义，有意义的是「比平时放大 2 倍」 | 原始日志 vs 聚合后的 QPS 曲线 |

所以模型吃的是**收益率、排名、比率、分位数**这类**无量纲**数字，不是「价格」和「手数」。

### 4.4 仓库里已经造好了

- `6_ml_datasets/features_daily/` —— 日频特征（技术指标 + 估值合并）
- `6_ml_datasets/l1_factors/` —— L1 因子（因子挖掘主力）
- [因子与特征参考](../QuantMind_因子与特征参考.md) —— Alpha158（158 维）+ 24 维微观结构 + 88 维基本面过滤

**所以第一步不是造特征，是读懂别人造好的特征**：挑 5 个，说清怎么算、为什么可能有用、有没有偷看未来。

### 4.5 一条铁律

> **每个特征，只能用「今天收盘时已经知道的信息」算出来。**

```python
# ❌ 错误：用了全天数据，但你是在当天开盘前决策
today_return = close / open - 1

# ❌ 错误：用了未来窗口（这是标签，不是特征）
future_5d = close.shift(-5) / close - 1

# ✅ 正确：只用截至今天/昨天的收盘价
ret_1d  = close / close.shift(1) - 1
mom_20d = close / close.shift(20) - 1
```

软件里叫「读到了不该读的状态」，量化里叫**未来函数**。详见 [03-常见陷阱与自检红线.md](03-常见陷阱与自检红线.md)。

## 5. 三种「打分」要分清（别混成「大模型」）

这个仓库里有**三种完全不同**的打分器：

| | 谁在打分 | 输出 | 要训练吗 | 你什么时候碰 |
|---|---|---|---|---|
| **传统 ML 模型** | LightGBM / XGBoost / GRU | 一个 `0.0021` 这样的数 | **要**（喂历史数据训练） | 第 13 周 |
| **规则因子** | 人写的公式（`1/PE`、20日动量…） | 一个数 | 不用 | ✅ **现在就用** |
| **大模型（LLM）** | DeepSeek / Qwen | 一段文字、一段代码 | 不训练，只调用 API | 现阶段别碰 |

- 所谓「模型分」，指的是**传统 ML 模型**的输出，不是 LLM。
- **LLM 在这个仓库里只干辅助活**：QuantBot 陪你聊天、RD-Agent 帮你写因子表达式。它**不产生「模型分」**，也不该直接用它的判断去下单。
- **三种都输出「分数」，三种都要在截面上排名。** 截面是数据形状决定的，跟打分器无关。

## 6. 怎么用这个仓库：三个身份

这是最重要的一节。**这个仓库有三个身份，每个身份只解决一个问题。但「从假设到结论」那段判断，三个身份都不给你，必须是你自己的代码。**

### 身份一：数据源 —— 解决「我没有数据」

**用它 = 只用 `data/quantdb/` 那个目录。** 不起 Docker、不起 4 个后端服务、不连 PG/Redis、不开前端。

```python
import duckdb
con = duckdb.connect()
df = con.execute("""
    SELECT "time" AS trade_date, wind_code AS symbol, close, volume
    FROM read_parquet('D:/quantmind_data/quantdb/1_kline_data/daily_forward/*/data.parquet',
                      hive_partitioning = true)
    WHERE dt BETWEEN 20200101 AND 20241231
""").df()
```

> 列名规范见 [quantdb_hub.py](../../backend/services/engine/data_platform/quantdb_hub.py) 的 `_COLUMN_RENAMES`：`time → trade_date`、`wind_code → symbol`；`dt` 是整数分区键（`YYYYMMDD`）。

**价值**：免掉 60GB 数据的抓取、清洗、复权、对齐、缺失处理——量化里最耗时间、最没有智力回报的部分，也是 90% 的人卡死的地方。

**反面用法**：为了「拿个数据」先把 docker-compose 起来、写 API 客户端。**你是来学量化的，不是来运维微服务的。**

### 身份二：参照物 —— 解决「正确做法长什么样」

**用它 = 读它的代码，不是跑它的功能。** 三个地方值得读：

| 读什么 | 你会学到 | 为什么值钱 |
|---|---|---|
| [ashare_matcher.py](../../backend/services/simulation/services/ashare_matcher.py) + [回测费用配置说明](../回测费用配置说明.md) | 涨跌停不可成交、停牌、整手、佣金/印花税/过户费、滑点怎么落地 | 「回测 25% → 实盘 3%」的元凶，自己拍脑袋一定漏 |
| [qlib_data_builder.py](../../backend/services/engine/qlib_data_builder.py) | parquet 怎么变 qlib 二进制、复权口径怎么对齐 | 复权搞错，因子全是未来函数 |
| [as16_momentum_20.py](../../strategy_templates/as16_momentum_20.py) 的 docstring | 一线踩坑记录 | 见下 |

as16 文档里的原话：

> 「模型分必须先做截面标准化……直接加 [-1,1] 的动量因子等于把排名完全交给动量（**实测 as11 年化从 55% 掉到 10%**）」
> 「直接调 `D.features` 会在每个调仓步重复拉全市场，把一年回测拖到几十分钟」

**这种「我踩过，你别踩」的记录，任何量化教程里都买不到。** 但你只能靠「读」拿到，点按钮拿不到。

### 身份三：对照组 —— 解决「我的策略到底行不行」

**用它 = 把 60 个模板当基准线（benchmark），不是当作业本抄。**

`strategy_templates/` 每个文件头部都有完整回测记录，例如 as16：

```
年化 65.05% ｜ 夏普 2.479 ｜ 最大回撤 -12.70% ｜ 基准 16.20% ｜ 胜率 54.81%
对照 standard_topk（同模型同区间）：年化 59.26% ｜ 夏普 1.918 ｜ 最大回撤 -18.42%
```

**这是一个现成的、免费的、同口径的对照组。** 你的策略必须在同区间、同费率、同模型分下打赢它，否则别自我安慰。

这是**证伪工具**。抄它的参数 = 抄别人的过拟合，换个时间段就死。

### 「核心研究自己写」= 不要只调 API，自己实现一遍核心逻辑

你招人时最怕什么？**会用框架搭 CRUD，但不知道 HTTP 底下发生了什么。** 量化里一样：**点按钮得到的是结论，自己写得到的是判断力。**

```
想法 → 数据 → 打分函数 → 检验有没有效 → 选股 → 加成本回测 → 归因 → 上不上线
```

**但「自己写」≠ 从零造轮子**：数据用它给的，回测引擎用 Qlib（微软开源，就是它的引擎），**你只写中间那段**。

## 7. 一个最小可跑的骨架（让你知道「做研究」长什么样）

```python
import pandas as pd

# 1) 把长表变成「日期 × 股票」价格矩阵
px = df.pivot(index="trade_date", columns="symbol", values="close").sort_index()

# 2) 你的第一个因子：过去 20 天涨跌幅的相反数（跌得多的可能反弹，叫「反转」）
rev20 = -(px / px.shift(20) - 1)

# 3) 未来 5 天涨多少（注意 shift(-5) 是往后看；这是「标签」，不是特征）
fwd5 = px.shift(-5) / px - 1

# 4) IC：你的因子排名与未来真实涨跌排名，相关性多高（每天一个数，再对时间求均值）
ic = rev20.corrwith(fwd5, axis=1, method="spearman").dropna()
print(f"IC 均值 {ic.mean():.4f}｜ICIR {ic.mean()/ic.std():.3f}｜样本 {len(ic)} 天")

# 5) 分层：按因子分 5 组，看收益是否单调
q = rev20.rank(axis=1, pct=True)
for g in range(5):
    bar = fwd5.where((q > g/5) & (q <= (g+1)/5)).mean(axis=1)
    print(f"第{g+1}组 年化 {bar.mean()*252/5:.2%}")
```

**跑完你会看到 IC 大概 0.03~0.06。** 这不是「3% 准确率很垃圾」——在日频 A 股，这已经是有用的因子了。详见 [03-常见陷阱与自检红线.md](03-常见陷阱与自检红线.md) 的自检红线。

**而这 20 行的第一版是「裸奔版」**：没有剔除 ST/停牌/新股、没有涨跌停不可成交、没有手续费。as16 那些 `f_*` 参数、matcher 里的规则，就是「补满版」。
**从裸奔到补满的每一步，就是你的学习路径。**
