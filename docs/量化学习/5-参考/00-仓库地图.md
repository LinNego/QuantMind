# 00 · 仓库地图：这个仓库到底能给我什么

> 一句话：**它是成品系统，不是教材。**
> 正确用法是把它当「数据源 + 参照物 + 对照组」，核心研究自己写。

---

## 1. 它是什么

QuantMind（量化大脑）OSS 是一个**一体化 AI 原生量化交易平台**，覆盖：

```
数据底座 → 因子挖掘 → 模型训练 → 批量推理 → 组合回测 → 模拟交易 → 生产监控
```

支持 A 股 / 港股 / 美股 / 期货 / 区块链五个市场，附带一个对话式机器人（QuantBot）和一个 LLM 因子演化框架（RD-Agent）。

| 层 | 技术 |
|---|---|
| 后端 | Python + FastAPI，单容器 4 服务（8000 api / 8001 engine / 8002 trade / 8003 stream） |
| 量化引擎 | 微软 **Qlib**（回测 + 模型） |
| 数据 | **Parquet + DuckDB**，本地 parquet 数据目录 `data/quantdb/` |
| 前端 | Electron + React + TypeScript |
| 编排 | Docker Compose（另含 PostgreSQL、Redis、Celery、QwenPaw 机器人容器） |
| 许可证 | **AGPL v3** |

**它的体量：源码约 80MB，`data/quantdb/` 全量数据约 60GB / 13.1 万个文件。**

## 2. 对你真正有价值的是哪四层

整个仓库九成代码对你现阶段无用。真正能拿走的是这四层：

| 层 | 落在哪里 | 对你的价值 | 怎么用 |
|---|---|---|---|
| **① 数据底座** | `data/quantdb/`（29 个数据集，定义见 [quantdb_datasets.py](../../../backend/shared/quantdb_datasets.py)） | ⭐⭐⭐⭐⭐ 免掉最痛苦的取数与清洗 | 用 DuckDB / pandas **直接读 parquet**，不起服务 |
| **② 回测与成本模型** | [ashare_matcher.py](../../../backend/services/simulation/services/ashare_matcher.py)、[回测费用配置说明](../../回测费用配置说明.md) | ⭐⭐⭐⭐⭐ 决定回测是不是真的 | **读代码**，把规则抄进自己的回测 |
| **③ 因子与策略菜单** | [strategy_templates/](../../../strategy_templates)（60 个模板）、[因子与特征参考](../../QuantMind_因子与特征参考.md) | ⭐⭐⭐ 当对照基准，不是当作业本 | 用它们的**回测记录**当 benchmark |
| **④ AI 层** | QuantBot / RD-Agent / Alpha Agent | ⭐⭐ 演示价值 > 学习价值，且要烧 LLM Key | 现阶段**完全忽略** |

**记住这个排序：①② 是资产，③ 是标尺，④ 是装修。**

## 4. 数据是怎么流动的（一条链看懂）

```
ModelScope 公开数据集（免费，约 60GB）        QuantDB SDK + API Key（付费，增量）
            │                                          │
            ▼                                          ▼
    modelscope_dataset_sync.py              quantdb_daily_sync.py
            │                                          │
            └──────────────► data/quantdb/*.parquet ◄──┘
                                    │
                    ┌───────────────┼────────────────┐
                    ▼               ▼                ▼
              DuckDB/pandas    PostgreSQL        Qlib 二进制缓存
              （你自己研究）    （平台业务用）    （回测引擎用）
```

**你只需要碰最左边那一段。** PostgreSQL 和 Qlib 缓存都是派生产物，需要时可以由 parquet 重建。

## 5. 「免费全量 / 付费增量」在代码里的准确位置

这不是产品策略，是两条技术路径，搞清楚能省你很多钱：

| | 免费全量 | 付费增量 | 免费兜底（很多人不知道） |
|---|---|---|---|
| 代码 | [modelscope_dataset_sync.py](../../../backend/services/engine/data_platform/modelscope_dataset_sync.py) | [quantdb_daily_sync.py](../../../backend/scripts/quantdb_daily_sync.py) | [daily_data_sync.py](../../../backend/scripts/daily_data_sync.py) |
| 来源 | ModelScope 数据集 `qusong0627/LightGBM_Alpha300` | QuantDB SDK | baostock → akshare → eltdx（通达信） |
| 要 Key 吗 | **不要** | **要 `QUANTDB_API_KEY`** | 不要 |
| 校验 | 逐文件 sha256 + size | 服务端 etag/sha256 | 无 |
| 断点续传 | 有（sqlite 状态库） | 有 | 视数据源 |
| 适合 | 首次建库、重建 | 每天补 T-1 数据、需要官方质量 | 只想省钱、日线级别够用 |

**关键结论：日线级别的增量你完全可以不付钱**，用 baostock/akshare 补，代价是质量与字段覆盖不如官方。详见 [01-数据获取与迁移.md](../2-阶段0/01-数据获取与迁移.md)。

## 6. 现在该看什么 / 直接忽略什么

### ✅ 现在只看这些

- `data/quantdb/` 的目录结构与 parquet（配合 [quantdb_datasets.py](../../../backend/shared/quantdb_datasets.py)）
- `quantdb_hub.py` 开头的**列名映射**（`time → trade_date`、`wind_code → symbol`）
- `ashare_matcher.py` + [回测费用配置说明](../../回测费用配置说明.md)
- `as16` / `as26` 两个模板文件（读文件头的注释，那是别人踩过的坑）
- `qlib_data_builder.py`（等到需要 Qlib 回测时再看）

### ❌ 第一次接触全部跳过（碰了纯浪费生命）

| 忽略项 | 为什么 |
|---|---|
| Electron / React 前端、所有页面 | 与你的研究无关，你不需要界面 |
| `docker-compose.yml`、部署脚本、Nginx | 你只用数据目录，不需要跑服务 |
| QuantBot、IM 机器人（微信/QQ/飞书）、技能中心 | 产品功能 |
| RD-Agent、Alpha Agent、「AI 自动挖因子」、所有 LLM 相关 | 门槛高、易过拟合、且要花钱 |
| 多市场（美股/港股/加密/期货）、AutoDL GPU 训练 | 你的战场先锁定 A 股日频 |
| 实盘对接（QMT / 通达信桥，默认 `ENABLE_REAL_TRADING=false`） | 至少 6 个月后再看 |
| 50 个模板里的 45 个 | 先留 `as16`（动量）和 `as26`（低波）当对照组 |

## 7. 关于 60 个策略模板：怎么用才不误导自己

每个模板文件开头都有类似这样的记录：

```
回测记录（模型 mdl_cn_train_...，2024-01-02 → 2024-12-31，A股费率/T+1/含交易成本）
    年化 65.05% ｜ 夏普 2.479 ｜ 最大回撤 -12.70% ｜ 基准 16.20%
    对照 standard_topk（同模型同区间）：年化 59.26% ｜ 夏普 1.918 ｜ 最大回撤 -18.42%
    注：单一区间单一模型的成绩只用于验证链路与相对比较，不等于未来收益。
```

**正确的读法**：

- ✅ 把它当**同口径对照组**：你的策略必须在同一区间、同一费率下打赢它
- ✅ 注意它自己写的免责声明：单区间单模型，不是收益承诺
- ❌ 不要抄它的参数。抄参数 = 抄别人的过拟合，换个时间段就死
