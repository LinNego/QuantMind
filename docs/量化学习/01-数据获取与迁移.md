# 01 · 数据获取与迁移：60GB 怎么最快弄到手

> 核心结论：**别在「公司下完搬回去」和「回去再下」之间二选一。**
> 正确的做法是 **① 先砍体积（只要 15~20GB）② 搬「时间」而不是搬数据 ③ 数据长期只放一台常开机器。**

---

## 1. 先搞清楚有多大

| 项 | 数值 | 来源 |
|---|---|---|
| 全量解压后 | **约 60 GB / 13.1 万个文件**（用户实测 59,606,711,644 字节、131,272 文件） | [QuantDB_数据包解压指南.md](../QuantDB_数据包解压指南.md) 第 5 节的校验输出 |
| 文档旧值 | 56 GB / 7.4 万文件 | 同上，已过期，以实测为准 |

| 体积分布 | `6_ml_datasets` 约 **39 GB（≈70%）**；`5_technical_derived` 约 9.3GB；`1_kline_data` 约 7.4GB；`2_base_sector` 0.4GB；`3_financial_data` 0.85GB | 同上 |
| 一键部署包（另一条路） | 约 **5 GB**（镜像 + 业务数据 + 预训练模型 + PG 备份） | [部署指南](../部署指南.md) |

**记住两个数字：60GB（全量）和 5GB（一键包）。差 12 倍。**

## 2. 三条获取路径

| 路径 | 免费？ | 速度 | 质量 | 适合 |
|---|---|---|---|---|
| **A. ModelScope 全量** | ✅ 免费 | 走国内 CDN，6 并发，可断点续传 | 逐文件 sha256 校验 | 首次建库、重建 |
| **B. QuantDB SDK 增量** | ❌ 需 `QUANTDB_API_KEY` | 快 | 官方口径最权威 | 每天补 T-1、要官方质量 |
| **C. 免费兜底增量** | ✅ 免费 | 慢 | baostock/akshare，字段少 | 日线够用、不想付费 |

- 路径 A 的代码：[modelscope_dataset_sync.py](../../backend/services/engine/data_platform/modelscope_dataset_sync.py)（**只需要 `httpx` + `pandas`，不需要 Docker**）
- 路径 B 的代码：[quantdb_daily_sync.py](../../backend/scripts/quantdb_daily_sync.py)（`_make_client()` 里没有 Key 直接抛错）
- 路径 C 的代码：[daily_data_sync.py](../../backend/scripts/daily_data_sync.py)（数据源优先级：QuantDB parquet → baostock → akshare → eltdx）

> **重要**：路径 A 建立的数据，**不需要任何 Key 就能被系统读取**。
> 见 [quantdb_local_scan.py](../../backend/scripts/quantdb_local_scan.py)：离线数据落地后扫一遍，把本地 parquet 的 md5/sha256 登记进状态库，后续增量同步直接命中 fast-path。

## 3. 砍体积：你 90% 的概率不需要 60GB

### 3.1 三档数据

| 档 | 包含的数据集 | 估算体积 | 够干什么 |
|---|---|---|---|
| **L0 精简** | 3 套日线 + 指数 + 基础板块 5 表 + 财务 8 表 + 估值/技术指标 + `features_daily` | **约 15~20 GB** | Qlib 入门、Alpha158、LightGBM、日频多因子、完整回测链路 |
| **L1 主力** | L0 + `l1_factors` | +10 GB 级 | 因子挖掘与模型训练主力 |
| **L2 全量** | + `l2_factors` + 1/5 分钟线 + tick | 60 GB | L2 微观结构 / 高频（**散户无优势，不建议**） |

### 3.2 两个可以直接砍掉的冗余

**冗余一：`l1_l2_factors` 是 `l1` + `l2` 的合并副本。**
仓库自己的 AutoDL 脚本默认把 `l1_factors,l2_factors,l1_l2_factors` **三个全拉**（[setup-autodl-native.sh](../../deploy/autodl/setup-autodl-native.sh) 的 `DEFAULT_DATASETS`），等于白下十几 GB。**三者取一即可。**

**冗余二：`6_ml_datasets` 占全量 70%。**
砍掉 `l2` / 分钟线 / tick，体积直接掉到 1/3。

### 3.3 时间裁剪（进阶，可选）

`dt=` 分区是按交易日切的。只保留近 5 年，体积大致再减半。
`modelscope_dataset_sync.py` 本身没有 `since` 参数，但 [setup-autodl-native.sh](../../deploy/autodl/setup-autodl-native.sh) 里有现成实现：

```bash
AUTODL_SINCE=2021-01-01 AUTODL_DATASETS=l1_factors bash deploy/autodl/setup-autodl-native.sh
```

（需要 WSL / Git Bash；纯 HTTP，同一套 sha256 校验。）

## 4. 带宽数学：先算，再决定

### 4.1 下载 60GB 需要多久（按 CDN 效率 50%~70% 打折）

| 下行带宽 | 理论耗时 | 实测预计 |
|---|---|---|
| 100 Mbps | 82 min | ~2.5 h |
| 300 Mbps | 27 min | ~45 min |
| 500 Mbps | 16 min | ~30 min |
| 1000 Mbps | 8 min | ~15 min |

**15GB 的 L0 档，耗时为上表的 1/4。**
→ 如果家里是 300M~500M 宽带，**「回去再下」其实只要半小时到 1 小时**，并不是「很久」。请先实测再判断。

### 4.2 从公司上传 60GB 到网盘需要多久

| 公司上行 | 60GB 上传 |
|---|---|
| 20 Mbps | ~6.7 h |
| 50 Mbps | ~2.7 h |
| 100 Mbps | ~1.3 h |

公司网络上行普遍很小。**所以「公司下 → 网盘 → 回家下」通常是最慢的方案**，除非公司有专线大上行。

### 4.3 移动硬盘搬运：13 万小文件是陷阱

直接拷目录，小文件随机写经常掉到 **5~20 MB/s**，60GB 要 **1~3 小时**。
**先打包成单文件再拷**：打包约 5 分钟 + 顺序拷贝约 5 分钟。

```powershell
# 打包（Windows 10+ 自带 tar）
tar -cf E:\quantdb.tar -C D:\QuantMind\data quantdb

# 到家解包
tar -xf E:\quantdb.tar -C D:\QuantMind\data
```

（Linux/macOS 同理；也可用 `robocopy /MT:16 /J`，但打包仍是更快的选择。）

## 5. 决策树：你该选哪条

```
公司机器能连 ModelScope 吗？
├── 不能 → 直接回家下（可远程开机提前启动），跳到「6. 操作步骤」
└── 能
    ├── 家里宽带 ≥ 300M？
    │   └── 是 → 不要在公司下大数据。回家前远程让家里机器开下 L0/全量，到家就好
    └── 家里宽带慢
        ├── 有移动硬盘 → 公司下 L0（≤20GB）→ 打包带走 → 回家 local_scan
        ├── 无硬盘但公司上行 ≥ 100M → 网盘传 L0
        └── 都没有 → 公司挂夜间下 L0（断点续传，第二天继续）
```

### 铁律一：搬「时间」，不搬「数据」

> **让你人还在公司的时候，家里那台机器就开始下。你到家时它已经下完了。**

下载器是**可断点续传**的（每批完成即写 sqlite 状态库，中断后重跑只补未完成项），所以挂着下、断网、重启都不怕。远程开机（WOL）/ 向日葵 / TeamViewer / Windows 计划任务，随便一个都行。

### 铁律二：公司机器只做下载

**别装 Docker、别跑服务、别起数据库。** 装一个 Python + 两个 pip 包就够。数据量大 + 公司设备，合规和 IT 政策风险要自己评估。

## 6. 操作步骤（可直接复制）

### 第 1 步：量体积（只读，5~10 秒，不下载任何数据）

```powershell
$env:QM_QUANTDB_DATA_DIR = "E:\quantdb"     # 也可以直接指向移动硬盘
pip install httpx pandas                    # 只这两个依赖

python -c "from backend.services.engine.data_platform.modelscope_dataset_sync import preflight_modelscope as p; import json; print(json.dumps(p(), ensure_ascii=False, indent=1))"
```

输出包含：每个数据集的 `files` / `bytes`、磁盘余量 `disk`、以及 `warnings`（空间不够会直接告诉你）。
**拿到真实数字再决定下哪档，别猜。**

也可以只问子集：`p(['daily_forward','features_daily'])`。

### 第 2 步：下载 L0 档

```powershell
$env:QM_QUANTDB_DATA_DIR = "E:\quantdb"
$env:MODELSCOPE_SYNC_WORKERS = "12"    # 默认 6；调太高会被 CDN 限流

python -c "from backend.services.engine.data_platform.modelscope_dataset_sync import init_from_modelscope as f; import json; print(json.dumps(f(['daily_forward','daily_unadjusted','daily_backward','index_daily','trading_calendar','instrument_detail','sector_concept','index_weights','margin_trading','balance','income','cashflow','capital','pershare_index','per_share','dividend_factors','holder_num','valuation','technical_indicators','features_daily','l1_factors']), ensure_ascii=False, indent=1))"
```

也可以在管理后台【数据管理】→【初始化数据】点按钮（同一个函数，能看进度、能取消）。

**下载器的行为**（读源码可知）：

- 从魔搭 tree API 分页枚举清单（含 sha256 / size），10 万条约 106 页，6 路并发约 5~10 秒
- 每个文件：`.part` → 校验 size + sha256 → `os.replace` 原子覆盖
- 失败重试 3 次；每批完成即写状态库
- 断点续传判据：**本地存在 + size 一致 + 状态库登记的 sha256 == 远端 sha256**

### 第 3 步：搬运（如果确实要搬）

见 [4.3](#43-移动硬盘搬运13-万小文件是陷阱)，先 tar 再拷贝。

### 第 4 步：换机器后让断点续传继续生效（**关键，最容易踩**）

**坑**：状态库路径是

```
~/.quantdb_state/quantdb_sync_<数据根路径转义>.sqlite
```

文件名由**数据根目录的绝对路径**生成（见 `quantdb_daily_sync._state_path`）。
所以换了机器、或换了盘符（`D:\quantdb` → `E:\quantdb`），状态库名就变了 → 系统认为你什么都没下过 → **重下 60GB**。

**解法**：在新机器上先跑一遍本地扫描，让它按新路径重建登记：

```powershell
$env:QM_QUANTDB_DATA_DIR = "D:\quantmind_data\quantdb"
python backend/scripts/quantdb_local_scan.py --root "D:\quantmind_data\quantdb"
```

扫描会计算每个文件的 md5 + sha256 并写入状态库（含 `--force` 强制重算选项，重复扫描会复用旧哈希，秒级完成）。
之后 `init_from_modelscope` 的续传判据就能命中，**只补真正缺的和变更的**。
60GB 全量首次哈希约 10~20 分钟，值得。

## 8. 长期架构建议（这一步决定你以后还会不会为这事头疼）

> **数据只放一台常开的机器上。**

- 家用台式机 / 小主机 / NAS，任意一台常开的机器
- `QM_QUANTDB_DATA_DIR` 指向它，QuantMind 需要时也部署在那台
- 以后增量只在那台机器上跑
- 公司机器 / 笔记本 / 手机前端都只是**客户端**

**从「每次搬 60GB」变成「机器一直在那儿」。**

## 9. FAQ

**Q：能不能只下某一年的数据？**
A：可以。`dt=` 是按交易日的分区，见 [3.3](#33-时间裁剪进阶可选) 的 `AUTODL_SINCE`。或在 `init_from_modelscope` 外层自己过滤文件清单（需要小改代码）。

**Q：下载断了怎么办？**
A：直接重跑同一条命令。已完成的文件会被跳过（需状态库命中，见第 4 步）。

**Q：怎么确认下载完整？**
A：下载器逐文件校验 sha256，`errors` 计数应为 0。完整校验可对比文件数与总字节：

```powershell
(Get-ChildItem -Recurse -File E:\quantdb | Measure-Object).Count
"{0:N0}" -f (Get-ChildItem -Recurse -File E:\quantdb | Measure-Object -Property Length -Sum).Sum
```

**Q：下载器支持 Windows 吗？**
A：支持。纯 `httpx` 流式下载，源码里还专门为 Windows 做了 `stat` 性能优化（见 `_scan_local` 的注释）。

**Q：`quantdb_sync.sqlite` 要一起拷吗？**
A：`data/quantdb/quantdb_sync.sqlite` 是 SDK 状态库，拷过去无害但**不足以让续传命中**（判据读的是 `~/.quantdb_state/` 下那份）。所以第 4 步的 `local_scan` 是必须的。

**Q：`releases/` 目录是什么？**
A：QuantDB 的发布清单（`releases/*/manifest.json`），`quantdb_local_scan` 会用它把每个数据集的最新 release_id seed 进状态库。L0 档不一定包含，没有也不影响读取。
