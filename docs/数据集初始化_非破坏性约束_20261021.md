# 数据集初始化（魔搭拉取）非破坏性约束（2026-10-21）

## 1. 用户红线

> 还有数据集初始化，不能把 quantdb 全部清空的，先拉远程的明细、远程有明细的可以清空。
> 不然万一点了一下就麻烦了。这个风险需要控制住。

解读：

1. 初始化**绝不能**「先清空本地目录再重拉」；
2. 必须先拿到远端清单，只处理清单里确实有明细的路径；
3. 一次误点不得造成不可逆的数据损失。

## 2. 现状核查（2026-10-21）

代码：`backend/services/engine/data_platform/modelscope_dataset_sync.py`
入口：`POST /api/v1/admin/data-platform/quantdb/modelscope/init`
UI：后台管理 → 数据管理 → QuantDB → 「初始化数据」

核查结论：**当前实现本来就不删数据**。

- 没有任何 `rmtree` / 目录清空 / 全库删除；全仓检索仅发现 `.part` 临时文件清理；
- 流程：分页枚举远端清单（`list_remote_files`）→ 按数据集分组 → 逐文件下载到
  `*.part` → 校验 size + sha256 → `os.replace` 原子覆盖；
- 远端清单里没有的本地文件、未勾选的数据集、以及其它数据集的同步状态登记，
  一律不触碰；
- 状态库重建只对**本次远端清单命中**的数据集执行
  `DELETE FROM objects WHERE dataset=?` 后按远端 sha256 回填——删的是同步记录，
  不是数据文件；
- 显式选择的数据集若远端不存在 → `ValueError`，任务不启动。

因此「点一下把 quantdb 全清空」在现有代码上不会发生。但为了把这条红线变成
**结构性约束**（防未来改动回归、防远端空清单导致的误导性完成回执），本次补了守卫。

## 3. 本次加固

### 3.1 空清单中止（新增硬守卫）

`init_from_modelscope` 在枚举后、任何本地写入之前检查：

```python
if total_files == 0:
    raise RuntimeError("魔搭远端清单为空（未枚举到任何可识别的 parquet 数据集）；已中止，未改动本地数据")
```

覆盖场景：远端仓库下线、API 异常返回空页、网络中间层返回空清单。
空清单不会再以「完成」姿态写状态库。

### 3.2 不变量写进函数契约

`init_from_modelscope` docstring 顶部明确：

- 从不删除本地文件/目录，也不清空数据根；
- 只覆盖远端清单列出的路径（`.part` → sha256 校验 → `os.replace`）；
- 远端没有的本地文件、未选中的数据集及其状态登记原样保留；
- 清单为空 → 任何本地写入之前中止。

### 3.3 UI 文案消除歧义

- 按钮 tooltip：补「不会清空本地目录——只覆盖远端清单内的文件，远端没有的本地文件原样保留」；
- 弹窗标题：`初始化数据 — 从魔搭拉取并覆盖远端清单内文件`；
- 弹窗说明：加粗「不会清空本地数据目录」，并写明空清单直接中止、不做本地改动。

## 4. 测试（先 RED 后 GREEN）

## 5. 风险边界（未做，说明清楚）

- **远端旧数据覆盖本地新数据**：逐文件覆盖是「与魔搭对齐」语义。若远端仓库
  落后于本地日更（例如本地已到 10-20、远端只到 09-30），同路径文件会被远端
  版本替换——这是**覆盖**而非删除，且只发生在远端清单列出的路径上；本地独有的
  更新分区不受影响。是否要在覆盖前比较分区日期、拒绝「远端更旧」的覆盖，
  需另行拍板（涉及「对齐魔搭」与「保留本地最新」的口径取舍）。
- 初始化不做全库清空，因此本地存在、远端已移除的历史文件会保留；如需严格镜像，
  应另设「按数据集清理」的显式动作并要求二次确认，不在本流程内隐式执行。
