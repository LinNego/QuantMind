## 0. 先说最重要的一句

**撤回前面基于 `simulate_lots()` 给出的这组数字**：

> 「5 万 + top20 + 立案剔除 + MA200 半仓 = 年化 20.7% / 回撤 -22.5% / Calmar 0.92」

理由：该模拟器的**账户账本**与**收益累乘**不一致（相差 2.56 倍），且用了信号日的复权因子去还原次日成交价。这两个都是 P1。在修好并重跑之前，资本/组合模式下所有 CAGR、回撤、Calmar、投入率都不可信。

单期的整手算术（例如「2026-09-30、20 只、每只 2,500 元预算、实际投入 43,487 元 = 87%」）是**静态计算**，与收益模拟无关，仍然成立。

## 2. P1 详述

### P1-1 选股前使用了未来的"可成交/有退出价"

**位置**：[backtest_low_price_small_cap.py:145-151](QuantMind/scripts/backtest_low_price_small_cap.py#L145-L151)、[:175](QuantMind/scripts/backtest_low_price_small_cap.py#L175)；[research_lowprice_drawdown.py:628](QuantMind/scripts/research_lowprice_drawdown.py#L628)、[:364-366](QuantMind/scripts/research_lowprice_drawdown.py#L364-L366)

`fwd_ret = o_out / o_in - 1`，其中 `o_out` 是**下一次调仓日**的开盘价。`universe()` 在排序选 top-k **之前**就要求 `fwd_ret.notna()`。

这等于用「明天能不能买」+「下个月还有没有退出价」来决定「今天选谁」。

**本机量化（ex_star 候选池）**：

| 项 | 行数 | 占比 |
|---|---:|---:|
| 面板总行数 | 519,501 | — |
| `fwd_ret` 为 NaN | 7,778 | 1.50% |
| 其中：**未来退出价缺失** | **2,740** | **0.53%** |
| 其中：T+1 开盘缺口 ≥ 涨跌停 | 4,667 | 0.90% |
| 其中：T+1 成交量为 0（停牌） | 513 | 0.10% |
| 其中：入场价缺失 | 498 | 0.10% |

> 注：交接文档里我之前写的「7,778 行 ≈ 1.5%，方向是低估收益」是**错的**。7,778 里有 2,740 行是「未来退出价缺失」，那部分方向是**高估**。两者不能混为一谈。

**对 top40 的实际影响**（只按信号日字段选股 vs 现行口径）：

- 5,091 个 top40 槽位中，**94 个（1.85%）** 因未来的入场/退出可用性被替换；
- 129 期里有 **56 期**至少换掉 1 只，平均每期 **0.7 只**，最多一期换 **25 只**。

**方向**：涨跌停那部分（4,667 行）是"当日涨停买不进"，剔除是对的但应发生在执行层；退出价缺失那部分（2,740 行）会提前删掉后来停牌/退市的票，**高估收益、低估尾部**。

**修法**：T 日截面只用 T 日可知字段排序；T+1 执行失败在执行层处理（明确"补位"还是"少买几只"）；持有期内缺价用停牌/退市估值规则，不能反过来剔除当期股票。

### P1-2 `simulate_lots` 的账本和报告的净值不一致（2.56 倍）

**位置**：[research_lowprice_drawdown.py:419-445](QuantMind/scripts/research_lowprice_drawdown.py#L419-L445)；覆盖发生在 [:876-877](QuantMind/scripts/research_lowprice_drawdown.py#L876-L877)、[:977](QuantMind/scripts/research_lowprice_drawdown.py#L977)

`simulate_lots` 第 430 行 `nav = cash + invested + gross` 是"现金 + 持仓"；但资本/组合模式随后又把它**覆盖**成 `capital × cumprod(1 + ret - cost)`。覆盖动作把两者不一致的事实藏起来了。

**复现（top20 / 5 万 / ex_star / 当前面板）**：

```
simulate_lots 原始末期 NAV : 1,323,022 元
逐期 (ret - cost) 累乘      :   516,688 元
比值                        : 2.561 倍
```

按年末看比值逐年恶化：2016 年 0.984 → 2020 年 2.109 → 2026 年 2.561。不是舍入误差。

**修法**：改成单一状态机（现金 + 真实股数 + 真实成交价 + 公司行动），每期断言 `NAV_t == NAV_{t-1} × (1 + net_return_t)`；**禁止在报告层覆盖账本**来"看起来自洽"。

### P1-3 用信号日复权比还原次日成交价

**位置**：[research_lowprice_drawdown.py:354-356](QuantMind/scripts/research_lowprice_drawdown.py#L354-L356)

```python
scale = snap.adj_close / snap.px.where(snap.px > 0)
real_in = snap.o_in / scale          # 假设次日复权因子 == 信号日复权因子
```

若信号日与入场日之间发生除权除息，这个假设不成立。

**实测（贵州茅台 600519.SH）**：

| 项 | 值 |
|---|---|
| 信号日 2016-06-30 复权比 | 1.000000 |
| 入场日 2016-07-01 真实开盘（不复权） | **287.20** |
| 入场日后复权开盘 | 293.402336 |
| 代码估出的真实开盘 | 293.402336 |
| **误差** | **+2.16%** |

（真实入场日复权比约 1.021596，不是 1.0）

**影响**：整手数量、现金扣款、持仓估值全错；误差跨过整数边界时会直接改变股数。

**修法**：直接读入场日的**不复权 open** 作为成交价（数据里 `daily_unadjusted` 有 open，只是当前面板没取）；真实持仓用原始股数，送转/拆股按生效日调整股数，现金分红单独入账。

## 3. P2 详述

### P2-1 换手成本用了当期未来收益

**位置**：[backtest_low_price_small_cap.py:245-261](QuantMind/scripts/backtest_low_price_small_cap.py#L245-L261)，核心是第 247-249 行

```python
grown = w_old * (1 + snap.fwd_ret.reindex(w_old.index).fillna(0))   # snap 是本期的未来收益
```

旧仓在**本次调仓前**的涨跌，应该用**上一期**的 `fwd_ret`；这里用了本期（未来）的。

**toy test（两只等权、篮子不变、cost=0.001）**：

| 本期未来收益 | 本期 turn | 本期 cost |
|---|---:|---:|
| (0, 0) | 0.00 | 0.0000 |
| (+50%, -50%) | **0.25** | **0.0005** |

只改未来收益就改变了当期交易成本。

**影响**：gross 收益不受影响，但 turnover / cost / net CAGR 被污染，方向不确定。

**修法**：缓存上一期已实现收益映射，用它漂移旧权重。

### P2-2 半仓/空仓的现金权重与费用记账

**位置**：[backtest_low_price_small_cap.py:230-260](QuantMind/scripts/backtest_low_price_small_cap.py#L230-L260)

四个独立问题：

1. `pos <= 0` 时直接清空 `w_old` 且 `cost=0` —— **空仓时的卖出成本完全没记**；
2. 首次建半仓仍走 `turn=1.0`，按 `2×cost` 收费 —— 应该只收买侧；
3. 持仓不变的**稳定半仓**，`grown` 被归一到 100%、目标 `w` 和为 50%，toy test 算出 `turn=0.25` —— 每期凭空多收 `0.25 × 2 × 0.175% = 0.0875%/月`；
4. 半仓 → 满仓时 `grown` 与 `w` 都归一到 1，算出 `turn≈0` —— **漏记从现金加仓的一半买入成本**。

**toy test 实测（cost=0.001，同篮子零收益）**：

| 场景 | 应有 | 实际 |
|---|---|---|
| 首次半仓 | 0.001（买侧） | 0.002 |
| 连续半仓第二期 | ≈0 | 0.0005 |
| 半仓→满仓 | 0.001（补买半仓） | 0 |

**影响**：所有 timing / MA200 系的回测成本口径都要重算，方向混合。

**修法**：权重向量必须包含 cash；按"上一期收益后的**总 NAV**"算各标的与现金的目标差额；买入/卖出分别计费。

### P2-3 缺价持仓用旧价卖出、缺失收益当 0

**位置**：[research_lowprice_drawdown.py:357-386](QuantMind/scripts/research_lowprice_drawdown.py#L357-L386)、[:419-430](QuantMind/scripts/research_lowprice_drawdown.py#L419-L430)

- `last_px` 存的是"入场价"，而不是"上一期末的退出价"；
- 若持仓股票下一期从面板消失（变 ST / 停牌 / 被过滤），第 379-385 行会**用这个旧入场价当成可卖价格**变现；
- `fwd_ret` 缺失在第 425-426 行被设成 0，等于"停牌/退市 = 价格不变"。

**合成反例**：A 以 10 元买 100 股，持有期 `fwd_ret = -50%`，下一期 A 缺行 → 程序按 10 元卖出，现金从应有的 500 元变成 1,000 元，**凭空多出 500 元**再加仓别的票。

### P2-4 立案过滤缺文件时静默失效

**位置**：[backtest_low_price_small_cap.py:331-357](QuantMind/scripts/backtest_low_price_small_cap.py#L331-L357)、[:590-607](QuantMind/scripts/backtest_low_price_small_cap.py#L590-L607)、[:665-672](QuantMind/scripts/backtest_low_price_small_cap.py#L665-L672)

`data/regulatory/events.parquet` 不存在 / 无 `category` / 无 investigation 行 → 返回空 blacklist，但日志仍打印「立案剔除：开」。而该目录被 gitignore，换台机器极容易缺文件。

**修法**：默认开时缺文件应报错或明确打印"过滤未生效"；只有显式 `--no-exclude-investigation` 才允许继续。

### P2-5 财务/风险字段 PIT 未验证

`is_quit_risk` 只做过类型漂移修复，没做过时点抽查（`is_st` 做过）。`pe_ttm` / `pb` / `net_profit_ttm` 是否按公告日滞后对齐也不清楚。影响「剔除亏损」「BP/EP」两条（结论都已被否决，但因子体检表要打折看）。

## 4. P3 详述

### P3-1 退市压测是情景模型，不是校正估计

**位置**：[research_lowprice_drawdown.py:449-517](QuantMind/scripts/research_lowprice_drawdown.py#L449-L517)

三个问题：

1. `p_base` 和 `loss` 是拍的，不是从真实退市样本估的；
2. 权重 2 / 1 / 0.5 的平均是 1.125，所以「池子平均退市率 2%」标签下，实际 top-k 的 hazard 是 4%；
3. 被击中后标的仍留在后续池里，可能被反复抽中 —— 真实退市应该终止持有。

所以 `stress` 输出的「top10 打折到 22.6%」只能叫**假设情景**，不能当"退市校正后年化"。

### P3-2 抓取部分失败仍返回成功

**位置**：[fetch_regulatory_events.py:137-212](QuantMind/scripts/fetch_regulatory_events.py#L137-L212)、[:273-288](QuantMind/scripts/fetch_regulatory_events.py#L273-L288)

切片请求失败会记入 `failed` 但继续；有失败仍写表并 `return 0`；翻页到 400 页上限也不核对 `totalAnnouncement` 是否取完。**部分缺漏会被当完整数据用**。

## 6. 修复顺序（按性价比）

1. **先停用小资金/整手组合数字**，把 `simulate_lots` 重写成单一账本，加 `NAV_t == NAV_{t-1} × (1+net_t)` 断言；
2. **把选股和执行解耦**：T 日只用 T 日字段选，T+1 执行/失败单独处理，退出缺价按停牌/退市规则；
3. **修 `run_strategy` 的换手状态机**（含 cash、前一期收益、买卖分别计费）；
4. **涨跌停判定改用真实 open 与真实前收**，别用"信号日复权比"估算；
5. 事件过滤 fail-closed + 抓取完整性校验；
6. 逐字段证实 PIT；
7. 全部重跑，旧数字作废。
