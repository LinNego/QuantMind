# 研究总控 · 多档复盘与次日共享（细案 2026-10-20）

> 用户口径（2026-10-20）：
> 1. 研究总控（`market-research`）要升级成**在其他 agent 之上**的总控：对系统、交易、对话、新闻、模型、经验、教训做总结；
> 2. 前端设置里**单独配置 API key / 端点 / 模型**；
> 3. 总控结论**第二天**要被其他 agent 看到；
> 4. 一天多档复盘：中午一次 → 收盘后各 agent 复盘出炉再一次 → 推理数据出来后一次 → 晚上 10 点多新闻复盘一次 → 最后综合给出**明天方向、资金判断、新闻、模型分数**。

## 1. 现状与缺陷（已核）

| 面 | 现状 | 缺陷 |
|---|---|---|
| 生成器 | `scripts/night_pool_agent.py` 只问 `market_view/sectors/pool` | 无持仓、无反馈、无经验教训、无新闻推演、无模型分数 |
| 展示 | 对话流走 `parseAnalysis` 四段解析 | JSON 原文被当散文；sectors/池不可见；总结只取 `market_view` |
| 次日共享 | 只把 `market_view[:80]` 写进池文件 `market_direction` | 80 字截断；完整报告写而不读 |
| 调度 | 只有凌晨 02:30 一次 | 无中午/收盘/推理/新闻档 |
| 配置 | 沿用 `GLM_*` / `OPENAI_*`，与交易模型共用 | 无法单独换 key/模型 |

## 2. 目标形态

```
交易日 D
 11:40  midday    ─┐
 16:20  close     ─┤  每档：读事实 → 调研究总控模型 → 报告落盘
 18:20  inference ─┤        → 追加对话流（market-research）
 22:45  news      ─┤        → 更新 brief/{D+1}（阶段结论）
 02:10  night     ─┘        → 汇总四档 + 全量事实 → 最终 brief/{D+1}
 02:30  night_pool_agent：读最终 brief，产 {D+1}_agent_picks.json（保留原契约）
 D+1 盘中：决策轮 / 对话轮读 brief 与池文件新增的 research_summary
```

- **独立配置**：`config/runtime.env` 的 `QM_RESEARCH_LLM_BASE_URL / MODEL / PROVIDER / API_KEY`；未配 key 时按模型前缀回落 `GLM_*` / `OPENAI_*` / `DEEPSEEK_*`（保证未配置也能跑，界面标注「回退」）。
- **单独 API key**：管理端 GET/PUT/test，key 只写不回，读侧只返回掩码。
- **报告结构**（固定七段）：市场与资金 / 持仓与交易复盘 / 对话与决策复盘 / 新闻与事件 / 模型与因子 / 经验与教训 / 明日方向与计划。
- **机读块**：报告尾部 ```json 围栏，含 `direction/capital/news/models/sectors/pool/risks`。
- **次日共享双通道**：
  1. `data/research_control/brief/{target}.md|json` → `night_pool_agent`（02:30 产池提示词）、`live_model_analysis`（对话轮）、决策轮（`RoundDeps.load_research_brief` → `RebalanceContext.research_block`，未接线/未产出时逐字节不出现）；
  2. `{target}_agent_picks.json` 的 `market_direction` 扩为 `direction/summary/capital/news/models/sectors/risks` → `decision_context_source` → `decision/context.py` 渲染（`direction` 仍是候选池就绪判据的唯一键）。

## 4. 数据面（全部容错，缺就写「缺口」，不编）

- 市场/资金：quantdb 最新日分区 breadth（涨跌家数、中位涨幅、成交额）+ 前一日对比 + 指数日线（`index_daily`）；盘中档补 TDX 桥指数快照（可失败）。
- 持仓/成交：`qm_agent_ledger_position` + `qm_agent_ledger_fill`（只给分账口径，绝不出现账户总资产）。
- 对话：`data/agent_data_astock/{agent}/log/{day}/log.jsonl` 最新摘要（截断）。
- 新闻：`data/news_brief/latest.json` + 当日 `history.jsonl` + `reviews/{day}.json`。
- 模型：`engine_signal_scores` 当日聚合（条数、多空分布、Top/Bottom、模型版本）。
- 经验：`market_memory.md` 尾部 + 近 3 日总控报告的「经验与教训」段。
- 系统：各产物新鲜度（quantdb 最新 dt、新闻 brief 时间、信号最新日、池文件是否存在）。

## 5. 验收（可复现）

1. `pytest backend/tests/test_research_control.py backend/tests/test_night_pool_agent.py backend/tests/test_decision_context.py backend/tests/test_live_model_analysis.py` 全绿。
2. `python3 scripts/research_control.py --slot midday --dry-run` 打印完整事实包，不写盘、不调模型。
3. 配 key 后 `--slot news` 实跑：生成 `data/research_control/reports/{day}/news.md`，对话流出现一张 market-research 卡片。
4. 次日 `live_model_analysis` 提示词含【研究总控·今日前瞻】；决策提示词含 `brief_for_prompt(target)` 渲染的【研究总控·… 交易日前瞻】。
5. `npm run typecheck` + `bash scripts/deploy_frontend.sh`；Playwright 验证设置页保存/测试与报告卡片全文渲染。
6. `crontab -l` 五档齐全。

## 6. 停止 / 淘汰判据（Kill criteria）

- 若关键 key 配置后连续 2 档 `finish_reason=length` 或空响应 → 停止上线，先把 `max_tokens/timeout` 与提示词长度压到位。
- 若交易日 D 的 `engine_signal_scores` 在 18:20 仍无当日数据 → inference 档只出「推理未就绪」报告，不伪造模型分数。
- 若 `decision_context_source` 改动导致既有金样测试出现任何非空 diff → 回退该块（默认空串必须逐字节等价）。
- 若 TDX 桥指数快照连续失败 → 市场块降级为「quantdb 最新日」，不重试、不阻塞。

## 7. 非目标

- 不让总控下单、不接 QMT、不改决策轮模型名册、不改变「agent 只见分账额度」的账户口径。
- 不把完整报告塞进决策提示词（只放 ≤1200 字的要点，避免挤掉盘口/新闻块）。
