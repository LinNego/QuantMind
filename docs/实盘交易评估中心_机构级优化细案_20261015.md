## 1. P0 供数链 bug

### B1【已实锤·每晚白烧数小时】EOD 五卡死循环：done 键永不落地

**实锤证据链**（2026-10-14 晚实测）：
- worker 日志：16:01→23:59 每 ~70s 一轮「五卡完成：落分=120 异常=1」，单晚 **411 轮**；`eval:scores:done:20261014` 在 trade Redis（db2）**始终为空**。
- 复现（no-save 全真跑）：`total_errors=1`，唯一 error 原文——
  `model:mdl_cn_train_20260922012829_017570fe_8589f2d2: 评分失败: pred 缺标签列（label / label_return 都没有）：无法评估预测力，拒绝按 0 计算`
- 根因：该模型是 stacking 集成模型（用户 10000001 于 09-22 训练），`pred.parquet` 只有 3 列 `trade_date, symbol, pred`；同批两个基模型（catboost/xgboost 后缀）均为契约 6 列 `symbol, trade_date, label, label_return, pred, split`（同为 9,125,407 行）→ **集成输出导出路径漏了 label 列**。
- 死循环机制：`eval_scores_service.py:164` 只在 `total_errors == 0` 时写 done 键 → 单点持续性错误 = 整晚每分钟重跑全量五卡。10-08 起每天如此。
- **影响面**：done 键无其他消费者（grep 全仓仅本文件），数据本身每轮都在 save（看板是新鲜的）→ 危害 = **每晚 ~400 轮 × 每次全量 90 模型 + 20 因子 + 5 策略 + 4 账户评分**的机时与 I/O 白烧，且此 bug 类（单点错误烧整晚）对任何未来错误都成立。

**修法（三层，建议全做）**：
- a. **数据修复**：为该模型 `pred.parquet` 按 `(symbol, trade_date)` 从同批基模型对齐补 `label/label_return/split` 三列（行数完全一致，join 可校验零丢失；不重跑训练）。
- b. **语义修复（model_card.py）**：`pred 缺标签列` 属**持续性数据缺陷**，不是可重试异常——改为写「不可评卡」（`score=None` + `low_confidence` + note 明示缺列），不计入 `errors`。前端覆盖条走斜纹缺省，如实展示"无法评估预测力"，保留"拒绝按 0 计算"的原则。
- c. **兜底硬化（eval_scores_service.py）**：done 键加**尝试预算**——同一日重试达 K 轮（建议 K=5）后落 done（值记当轮 errors），并 WARNING 日志/告警。任何未来单点错误不再烧整晚。

**验收**：修复当晚 done 键落地、日志中「五卡完成」= 1 次；`/api/v1/eval/scores?object_type=model` 中该模型卡变为"缺省卡"且带缺列原因（或补数据后正常出分）；后端测试补 3 例（缺标签卡、尝试预算、done 键语义）。

### B2【观察·待实施首日核实】strategy_health 只有 3 行且停在 10-11

回测完成自动落档钩子（`backtest_health.py:378/424`）疑只在 strategy_id 为纯数字时生效；大量回测以 `backtest_id` 存而非策略 id → 体检档案覆盖极窄。修法：核实钩子条件，按 `qlib_backtest_runs → strategy_id` 映射补齐；月度复检（`health_recheck`）同样核对覆盖面。

### B3【观察】strategy 卡展示名 4/5 解析为 None

`strategy` 卡 `object_id = backtest_id`，`config_json` 里没有 `strategy_name/symbol` → 前端只能显示 `backtest_id`。修法：`eval_scores.py:_resolve_display_names` 的 strategy 分支改为 `qlib_backtest_runs → strategies.name` 关联取名（一条 SQL 的事）；写明回落链：strategy.name → config_json.name → `回测 · {symbol} · {区间}` → backtest_id。

## 2. P1 机构级功能缺口（"功能完善"）

### F1【最大功能洞】「实盘交易评估中心」没有实盘账户评估卡

现状：account 卡只扫模拟盘（`simulation:account:*`，实测 82 行全是模拟账户）；**实盘台账**（`real_account_ledger_service`，日频端点 `/api/v1/real-trading/account/ledger/daily` 已在线上供数）**完全未接评估侧**。用户已跑 QMT/TDX 实盘数月，中心里看不到实盘账户的收益/回撤/风险事件/资金利用率——名不副实的"实盘"评估。

修法（推荐）：新增第 7 类卡 `live_account`（object_type 新枚举）
- 读面：`/object-types` 增加一类；`_resolve_display_names` 加分支（`{user}:{market}` → 同 account 口径）。
- 写面：EOD 五卡 → 六卡，`account_card.py` 复用四维评分（30/20/25/25），数据源换成实盘台账（净值=账户日快照、回撤同口径、风险事件用真实状态词表）。
- 前端：TYPE_ICONS 加一枚图标；维度覆盖条/一问一图槽位（净值曲线 + 回撤 + 风险事件 3 图）。
- 备选形态：account 卡内加 `mode=SIM/REAL` 分档（改动小但语义混杂，不推荐——模拟与实盘的口径与金额完全不同源，混在一个榜里排行不成立）。

### F2 一致性维恒缺省（strategy 卡 20 分永远拿不到）

`strategy_realized.consistency_dim()` 永远 insufficient（"回测↔模拟/实盘曲线对照未接入评估侧"）。修法：接入 sim/实盘台账曲线与回测曲线做跟踪误差对照（`backtest_health.py` 已有 tracking_error 口径可复用）。工作量中等，建议本批做数据对接、下批上线。

### F3 体检档只看得到模拟预演 + 资格清单未渲染

- 前端 `getStrategyHealth` **不传 mode** → 永远拿到 SIMULATION 预演门禁；REAL 资格（SIM≥20 交易日、跟踪误差≤0.15）后端已完整返回却无人看。
- `eligibility{SIMULATION,REAL}` 的逐项清单（key/label/passed/reason/next_step）**前端一个字段都没画**（`HealthArchivePanel` 只画 latest/gate/history）——这是"半成品感"最重的一处。
- 修法：体检档案面板加 SIM/REAL 切换 + 逐项资格清单渲染（放行/拦截徽章下逐行展示理由与下一步）。

### F4 非 CN 账户卡无净值序列（v1 已知缺省）

`account_card` 对 hk/us 明确注明"净值序列未按市场分表，不误用 CN 序列"。A 股优先原则下本批**不做**，在卡片 note 呈现口径说明即可（如实标注优于硬造）。
