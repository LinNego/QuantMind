# 组合选股 · 周期收益统计 细案（2026-10-21）

> 用户需求（原话）：
> 「滚动建仓 统计的数据，能按月统计吗？给一个时间段、比如每月 1 号建仓开始，到月底滚动后的数据、或者最近半年 自定义时间。然后统计收益、根据我定义的模板，分配多少资金。可以筛选持仓比如 20 只，最多 50 只。计算这个周期的收益和收入。可以用于看这个模型综合选股的盈利能力。」
> 追加口径：「增加一个建仓日、后面时间选择长，可以拉长到、因为都是滚动到。统计总收益。去掉滑点、双边手续费这些。」

## 1. 目标

在「组合选股 · 滚动建仓」旁增加**周期收益**视图：给定建仓日与截止日，用**已保存组合的模板参数**（每日新进 `entry_per_day`、持有 `rolling_window`）和用户填写的初始资金、持仓上限，模拟固定持有期的滚动组合，输出：

- 区间总收益（%）与收益金额（元）；
- 月度拆解（每月收益、收益金额、建仓/了结笔数、月末持仓）；
- 每日权益曲线（供前端画图与最大回撤）；
- 全部已了结交易的明细。

用途：评估该模型组合**综合选股的盈利能力**，不是交易执行台账（无委托、无成交、不写 orders/sim_trades）。

## 2. 数据现实（2026-10-21 实测）

- `engine_signal_scores` 共 19.7M 行；`qm_model_inference_runs` 已完成 1938 个 run（2026-01-05 ~ 2026-10-20）。
- 当前 13 模型组合 `bl_6daa88ed49ea4bcc991a30a1`（全13·T+10 等权，E=5 / H=10 / P=50，min_coverage=8）**只有 32 个评分日**：2026-08-27 ~ 2026-10-19（8 月 3 天、9 月 21 天、10 月 8 天）。
- 因此「最近半年」对当前组合**不可完整填充**：必须把有效区间夹到可用评分日，并明确告警；**绝不伪造缺失日/补 0**。
- 另一个组合 `bl_e265dee0ae0341daa2aaab79`（E=1 / H=10 / P=10）同样只有近期数据。

## 3. 组合模型（固定持有期滚动桶）

与《2026TopK组合回测_细案_20261019.md》的滚动 TopK 方法、以及模板参数语义一致：

- **交易日历**：区间内每个 A 股交易日都推进组合；只有**评分日**才建仓。
- **建仓**：评分日 `D` 收盘，从当日组合分榜单前 `P` 名中按顺序取前 `E` 个**未持有**标的；现金不足或持仓已满 `P` 即停止。
- **持有**：每笔持有 `H` 个交易日；`D` 收盘建仓 → `D+H` 收盘退出（`D` 记为持有第 1 日）。
- **退出**：到期日收盘价退出；到期日无有效收盘价（停牌/缺数据）→ **顺延到下一个有收盘价的交易日**退出，不拿旧价假装成交。
- **仓位**：初始资金 `C` 按持仓上限 `P` 等分，每笔目标金额 `C/P`（不超过可用现金）；允许**小数股**（不引入整手取整噪声，手续费/滑点按用户要求全部不计）。
- **估值**：每日收盘用当日有效收盘价逐笔市值 + 现金 = 权益；期末未到期持仓按最后一个有效收盘价计**浮动盈亏**，计入总收益。
- **不重入**：已持有标的不加仓；退出后再次入选按新的一笔计。
- **无费用**：`fee_convention="none"`，不收佣金/印花税/过户费，不扣滑点。

> 为什么不按「每日等权 TopK 次日换仓」：用户明确要求「根据我定义的模板」建仓并滚动到截止日；模板的 `entry_per_day × rolling_window = target_positions` 就是固定持有期滚动桶。现有「滚动建仓」页的窗口涨跌（每日换仓复利）保留不动，两者口径不同，页面分别标注。

## 4. 参数

| 参数 | 来源 | 默认 | 约束 |
|------|------|------|------|
| `start` 建仓日 | 用户 | 可用评分日最早一天 | ≤ `end` |
| `end` 截止日 | 用户 | 可用评分日最新一天 | ≥ `start` |
| `capital` 初始资金（元） | 用户 | 10,000,000 | (0, 1e12] |
| `positions` 持仓上限 P | 用户 | `min(模板 target_positions, 50)` | 1–50 |
| `entry_per_day` E | **模板** `blend.entry_per_day` | 模板值 | 1–50 |
| `hold_days` H | **模板** `blend.rolling_window` | 模板值 | 1–60 |

- 前端只让用户改 `start / end / capital / positions`；E、H 只读展示（「根据我定义的模板」）。
- 当 `P < E×H`：组合会在满仓后暂停建仓，返回 `positions_cap` 告警。
- 当 `P > E×H`：稳态下永远填不满，返回 `underfill` 告警（资金利用率偏低）。

## 6. 月度统计口径

- 按自然月分组；月份的第一/最后一行取该月内实际模拟交易日。
- 月收益 = `月末权益 / 上月末权益 − 1`；首个自然月以上一期为**建仓日初始资金**（不是月初的虚拟权益）。
- `profit_amount` = 月末权益 − 上月末权益（元）。
- `entries` = 当月建仓笔数；`exits` / `closed_trades` = 当月了结笔数；`win_rate_pct` 只统计当月了结且有价交易，`null` 表示当月无了结（展示 `—`）。
- 区间首月/末月不完整时 `partial=true`，前端标注「不完整月」。

## 7. 数据质量守卫

1. **有效区间**：`effective_start` = 请求区间内第一个评分日；`effective_end` = 请求区间内最后一个评分日与最后一个有行情的交易日取小。夹取即告警。
2. **评分覆盖率** = 评分日数 / 区间 A 股交易日数；<30% → 422；30–80% → `data_quality="partial"`；>80% → `complete`。
3. 评分日不足 2 → 422（无法形成滚动周期）。
4. 缺价建仓：跳过该标的并计数告警；缺价退出：顺延；期末无有效价：用最近有效价并标 `stale_mark`。
5. 行情源不可用：直接 422，**不返回全 0/全初始资金的假结果**。

## 8. 性能预算与快路

现有 `_window_stats` 对 32 天实测 ~11.8s（其中 ~10s 耗在逐行正则折叠符号）。本功能新增 `_range_stats`：

- SQL 先按 `(data_trade_date, 原始 symbol)` 聚合 `SUM(pct×w)`、`SUM(w)`、`coverage`、`consensus`（每组约 5k 行/日）；
- Python 再用 `StockCodeUtil.to_prefix` 折叠前缀并合并，排序取前 P；
- 已对拍验证：32 天、13 模型与 `_window_stats` 的分数/顺序 **diff = 0**（四舍五入到 1e-10）；快路查询 2.77s + 折叠 1.26s ≈ 4s。
- `mean` 走快路；`median/trimmed` 复用 `_window_stats`（区间上限 120 个交易日，超出 422 并提示切换区间）。
- 结果按 `(tenant,user,members,method,trim,min_coverage,consensus,start,end,top_k)` 进程内缓存 120s（历史日结果落定后不变）。

## 9. 淘汰/停止判据（kill criteria）

任一命中即停止本迭代，不做「先上线再补」：

1. **K1 正确性**：快路与 `_window_stats` 在任一测试日分数/顺序不一致（容差 1e-9）→ 废弃快路，改用既有 SQL。
2. **K2 数据不足**：当前组合评分日 < 2 → 前端只显示空态与可用区间，不计算、不伪造。
3. **K3 行情不可用**：无法取得收盘价 → 422 `quote_source_unavailable`，不产出结果。
4. **K4 性能**：支持区间（≤300 交易日）首调 > 60s 或响应 > 20MB → 本迭代不上同步接口，改异步任务（另立细案）。
5. **K5 口径**：任何缺失价格被写成 0 / 初始资金被当成收益 → 视为阻塞缺陷，修完再交付。
6. **K6 合规**：展示面出现「买入/卖出」或把月收益写成投资建议 → 阻塞，改回「建仓/退出/入选」。
