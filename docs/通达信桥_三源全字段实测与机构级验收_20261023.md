## 5. 稳定性与可靠性

### 5.1 并发风暴（worker 直连）

| 风暴 | 结果 |
|---|---|
| 重接口 12 路（kline） | 1×200 + **11×503（49ms 内）**，无排队 |
| 轻接口 30 路（quote） | 9×200 + 21×503（≤2s 内拒绝） |
| 风暴后 | `connected=true`，闸门归零 |

**压测暴露并修复的三个结构性问题**：

1. 上游 MAIN 连接是一把 `_sock_lock` 串行管道：32 路并发把请求堆进线程池，重接口队头阻塞 → 轻请求全超时、会话被拖断且**心跳是 observe_only 不自愈**。
2. 一次上游挂死（`history_timeline` >45s 不返回）会**永久占住**重接口闸门。
3. worker 的「忙 503」被桥计入熔断，5 次就把 THS 旁路熔断 30s，全部流量跌回 TDX。

**修复**：
- worker 分级闸门（重=1、轻=3）+ 轻请求在重接口在跑时**立即 503**；
- 单请求硬超时（重 30s / 轻 8s）→ `shutdown` MAIN socket 触发自愈 + 20s 断线重连看门狗；
- 桥侧出站闸门 4 路 / 0.3s；**忙 503 不计熔断**；超时单独计权（10 次才熔断，传输错误 5 次）。

### 5.2 可靠性验证

- 风暴后连续 5 次单请求全部 200，熔断计数归零；
- `board_quotes` 上游挂死 → 30s 504 + 自愈，随后 `connected=true`；
- 桥看门狗（`TDXBridgeWatchdog`）与 worker 计划任务（`TdxThsWorker`）均在跑；桥进程被 kill 后 40–90s 内自动恢复。

## 6. 安全审计

| 项 | 结果 |
|---|---|
| 鉴权 | 非白名单端点**全部 401**（47 条路由矩阵）；白名单仅 `health/ui/cache kline/get` |
| Token | `hmac.compare_digest` 常数时间比较；日志不落明文 |
| 限流 | 未鉴权 600/分（部署值）、鉴权 6000/分；**5 次鉴权失败封 IP 30s**（实测触发） |
| 请求体 | >512KB → **413**（600KB 实测） |
| CORS | 无 `Access-Control-Allow-*`，浏览器跨域读被挡 |
| 网络暴露 | worker `:8765` 仅 `127.0.0.1`；采集器外部不可达；桥 `:8550` 对 LAN（无 TLS） |
| 写操作 | `/tdx/call` 收紧为**只读白名单**：`exec_to_tdx/send_file/formula_set_data/create_sector` 全部 403；aidata 只放行只读方法 |
| 注入 | 路径穿越 `..%2F`/`%00`/非法方法/板块名 全部 400；`_CODE_RE` + `_BOARD_RE` 双重校验 |
| SQL | 缓存库无 f-string 拼接查询 |
| **修复的泄露** | `/api/v1/stats` 曾**匿名返回实盘余额/资产/持仓数**（违反「总资产永不可见」）→ 已改为需鉴权，UI 同步带 token；`/api/v1/system` 同样收紧 |
| **遗留** | 部署机 `config.yaml` 仍有明文 token（已 ACL 收紧到 ESXI/SYSTEM/Admins）；迁移到 `BRIDGE_AUTH_TOKEN` 环境变量需用户授权（本轮被权限闸拦下） |

> 事故记录：本轮误把仓库 `config.yaml` 覆盖到部署机，触发桥的「token 缺失自动生成」逻辑，token 被静默轮换、平台 401；已用 stdin 管道恢复并验证 200。教训：**部署只传代码文件，绝不覆盖配置**。

## 7. 缺陷与修复清单（21 项）

**代码审计（12）**：单飞 owner 取消连坐；裸码指数/个股歧义；aidata 无超时且持锁挂死；`status()` 锁外查 DLL；取消订阅无超时；CRLF ini 读不到 token；板块名未 URL 编码；`change_pct` 源缺失；订阅启动超时孤儿；`ths_compare` 单位/源不一致；配置键放错节；QR 启动竞态。

**压测/实测（9）**：忙 503 误熔断；上游挂死永久占闸门；worker 无并发闸门；轻请求被重接口拖 8s；代码格式（裸码/前缀）全部源失败；TDX 金额浮点尾差；THS 盘口股/手混用；板块码被股票正则拒绝；`/stats` 账户泄露。
