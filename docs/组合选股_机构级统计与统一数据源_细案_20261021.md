# 组合选股 · 机构级统计与统一数据源（细案）

- 日期：2026-10-21
- 触发：用户指出「组合选股数据日只到 8.27」「滚动建仓的统计数据准确吗？浮动和收益怎么区别」「超额也没有统计」「不够专业」「数据端口要统一」
- 范围：推理中心 → 组合选股的两个 Tab（周期收益 / 滚动建仓）及其后端数据面
- 不改：当日榜单 `ranking()` 的实时口径；单模型「截面选股 → 历史统计」的既有口径

---

## 一、问题诊断（已实测，非推测）

### 1. 数据端口不统一

| 视图 | 数据源 | 实际覆盖 |
|------|--------|----------|
| 组合选股 · 周期收益 / 滚动建仓 | `qm_model_inference_runs` + `engine_signal_scores` | 2026-08-27 → 2026-10-19，**32 个交易日** |
| 截面选股 · 历史统计（单模型） | 模型目录 `pred.parquet` 的 `split='test'` | 2025-02-05 → 2026-10-19，**414 个交易日** |

13 个成员模型的 pred 测试集都覆盖 414 天；组合视图却只读最近 32 天的推理运行记录。这是「只到 8.27」的唯一根因。

### 2. 两个数据面在重叠区间数值等价（已验证）

- 按模型、按日对 `pred` 做 `PERCENT_RANK()`，与 `engine_signal_scores.rank_pct` 逐值比较：
  - 最大绝对差 **0.0**，Spearman **1.0**，Top-50 名单重合 **50/50**。
- 结论：把组合历史切到 pred 测试集，**不改变重叠日期的任何排序结果**，只是把区间前推到 2025 年初。

### 3. 浮动与已实现未分栏

- 周期收益后端 `simulate_period` 已产出 `realized_pnl_amount` / `unrealized_pnl_amount`，但前端只显示总收益，两个金额从未露出；也没有收益率口径。
- 滚动建仓后端 `compute_rolling_performance` **完全没有金额口径**：只有 `open_avg_return_pct` 一个「浮动」百分比，已实现盈亏不存在。

### 4. 滚动建仓的统计口径自相矛盾（「不准确」的根因）

`compute_rolling_performance` 同时输出两种互不相同的组合：

1. `cycle_return_pct`：**每日等权换仓**组合（今日 TopK 收盘持有到次日收盘）；
2. `closed_trades` / `win_rate_pct` / `avg_return_pct`：**窗口内连续在榜才持有**的另一套「组合」。

两者的持仓、换手、收益都不是一回事，却并列展示为同一个策略的成绩。窗口首列入场的标的还带 `entry_from_window_start=True`（入场价并非真实入选价），其收益被计入胜率。

### 5. 无基准、无超额、无风险指标

- 组合周期/滚动的引擎里 `benchmark` / `excess` 出现次数为 **0**；单模型历史统计早已有沪深 300 基准与超额。
- 无年化、波动率、Sharpe/Sortino/Calmar、信息比率、盈利因子、盈亏比、换手、平均持仓天数、仓位暴露。

### 6. 区间上限与默认窗口

- `MAX_PERIOD_TRADING_DAYS = 300`（约 14 个月）、`MAX_NON_MEAN_PERIOD_DAYS = 120`，pred 全测试集 414 天会被拒。
- `period()` 默认 `target_end - 180 天`，即使切到 pred，默认视图也只到 2026-04；快捷区间锚点取自 `/dates`（runs 日期），同样只到 8 月底。

## 二、口径决策

### D1. 组合历史统一走 pred 测试集（按组合整体选源，不混源）

- 一个组合的全部成员都能解析到 pred 且测试集区间非空 → `source = "pred"`；
- 否则 → `source = "runs"`（现状），并返回 `source_fallback_runs` 警告；**绝不在同一组合内混用两个数据面**。
- 当日榜单 `ranking()` 继续走 runs：它服务的是「现在」，不是历史统计。
- 响应新增 `source` 与 `bounds`，前端显式标注数据源，用户能看见自己看的是哪套数据。

### D2. 两种视图各自对应一个、且只有一个组合模型

| 视图 | 组合模型 | 换仓节奏 |
|------|----------|----------|
| 周期收益 | 固定持有期滚动桶：每日新进 `entry_per_day`，持有 `hold_days` 个交易日后收盘退出，资金按 `positions` 等分 | 到期换仓 |
| 滚动建仓 | 每日等权换仓：每日收盘按当日 TopK 等权建仓，次日收盘全部换出 | 每日换仓 |

- 滚动建仓的**交易统计改为「每日批次」**：批次 = 某日 TopK 的一篮子，次一交易日收盘结算；最后一日批次为未结算（浮动）。
- 「连续在榜天数」只保留为**名单可视化**（`held_days` 列），不再参与任何胜率/盈亏统计；`exits` 明细改称「在榜区间涨跌」，不再叫交易。
- 这消除了 D4 的双口径矛盾。

### D3. 已实现 / 浮动 的定义

- 已实现盈亏 = Σ(已结算批次或已到期持仓的卖出金额 − 建仓金额)；
- 浮动盈亏 = Σ(未结算批次或未到期持仓的期末市值 − 建仓金额)；
- 合计 = 已实现 + 浮动，且必须等于 `期末权益 − 初始资金`（测试用恒等式锁死）；
- 收益率分母统一为**初始资金**：`realized_return_pct = realized_pnl_amount / initial_capital × 100`，浮动同理。
- 缺价：不建仓、不猜价；未结算批次的缺价标的保留上一有效价并计 `stale`，在质量块披露数量。

### D4. 基准与超额

- 基准：沪深 300（`000300.SH`），与单模型历史统计一致；前复权/指数收盘价，来源 `QuantDBDataHub.fetch_index_kline`。
- 基准收益：区间首个交易日收盘 → 最后交易日收盘；组合第一日无持仓，二者同起点。
- 超额 = 组合收益 − 基准收益（算术差，报表口径）；另给信息比率 = 日均超额 / 超额标准差 × √244。
- 月度：每月首/末交易日的基准收盘计算基准月收益，超额 = 组合月收益 − 基准月收益。
- 基准缺失的交易日：收益记 `None`，不写 0；整段基准覆盖率 < 95% → 基准/超额/信息比率一律 `—` 并给 `benchmark_unavailable` 警告。

### D5. 指标定义（全部为「未计费用」口径，页面持续披露）

| 指标 | 公式 |
|------|------|
| 累计收益 | `final_equity / initial_capital − 1` |
| 年化收益 | `(final/capital)^(244/trading_days) − 1`；`trading_days < 20` 时为 `None`（样本太短不年化） |
| 年化波动 | `std(日收益, ddof=1) × √244` |
| Sharpe | `mean(日收益)/std(日收益) × √244`（rf = 0，披露） |
| Sortino | `mean(日收益)/下行标准差 × √244` |
| 最大回撤 | `min(equity/peak − 1)`，并记录峰值日/谷底日 |
| Calmar | `年化收益 / |最大回撤|` |
| 信息比率 | `mean(日超额)/std(日超额) × √244` |
| 盈利因子 | `Σ盈利金额 / |Σ亏损金额|`（按已结算交易或批次） |
| 盈亏比 | `平均盈利% / |平均亏损%|` |
| 换手（倍） | `Σ建仓金额 / initial_capital` |
| 平均暴露 | `mean(持仓市值/权益)` |
| 平均持仓天数 | 已结算交易/批次的持有交易日均值 |

- 胜率只按**已结算交易/批次**计；未结算批次只进浮动，不进胜率分母。
- 所有 `None` 前端显示 `—`，**绝不显示 0**（沿用项目既有约定）。

## 三、后端设计

### 3.1 新模块 `backend/services/engine/inference/portfolio_metrics.py`（纯函数）

```python
def drawdown_stats(days, equity) -> dict            # 回撤 + 峰/谷日期
def risk_metrics(daily_returns, *, periods=244) -> dict
def benchmark_stats(days, benchmark_closes) -> dict # 区间收益、日收益、月收益、覆盖率
def trade_stats(trades) -> dict                     # 盈利因子/盈亏比/平均盈亏/持仓天数
def monthly_benchmark(months, days, benchmark_closes) -> dict[str, float | None]
```

- 全部无 IO、无状态；输入缺失值一律返回 `None`，由上层序列化。
- 日收益序列的构造：`equity_t / equity_{t-1} − 1`，首日收益为 0（当日无持仓，权益=初始资金）。

### 3.2 新模块 `backend/services/engine/services/blend_pred_source.py`

职责：把「组合成员 → 每日 TopK 榜单」从 pred.parquet 还原出来。

- `resolve_member_pred(member, tenant_id, user_id)`：复用 `resolve_effective_model` + `resolve_pred_candidates`，返回 `(pred_path, mtime)`；按 `(tenant,user,model)` 缓存 300s。
- `load_ranked_rows(members, weights, method, trim_count, min_coverage, start, end, top_k)`：
  - DuckDB 一次扫描全部成员的 `pred.parquet`（每文件打 `model_id` 标签），`WHERE split='test' AND trade_date BETWEEN ? AND ?`；
  - `PERCENT_RANK() OVER (PARTITION BY model_id, trade_date ORDER BY pred)` → 与 DB `rank_pct` 同一口径；
  - 按日、标的聚合：`coverage = COUNT(*)`，`score` 按 method（mean 加权 / median / trimmed）；
  - `QUALIFY ROW_NUMBER() OVER (PARTITION BY trade_date ORDER BY score DESC) <= top_k` 下推；
  - 返回 `dict[date, list[{"symbol","score","rank","row_rank","coverage","pct"}]]`，符号统一为前缀式（pred 原生前缀，保持不变）。
  - `memory_limit='2GB'` + `temp_directory`，在 `asyncio.to_thread` 中执行。
- `pred_bounds(members)`: 每个成员测试集首/末交易日，取 `min(end)` 与 `max(start)`，返回 `members_ready / members_total`。
- 聚合语义必须与 `_window_stats` 对齐（同 method、同 trim_count、同 min_coverage）；用重叠日（2026-08-27 起）做金样对照测试。

### 3.3 `bound` 分派

`ModelBlendService` 增加：

```python
async def data_bounds(blend, *, tenant_id, user_id) -> dict
```

返回：

```json
{
  "source": "pred",
  "pred": {"start": "2025-02-05", "end": "2026-10-19", "trading_days": 414,
            "members_ready": 13, "members_total": 13},
  "runs": {"start": "2026-08-27", "end": "2026-10-19", "trading_days": 32},
  "effective": {"start": "2025-02-05", "end": "2026-10-19"},
  "warnings": []
}
```

`period()` / `rolling()` 统一调用：

```python
rows_by_day, source, bounds, source_warnings = await self._history_rows(...)
```

`_history_rows` 内部分派 pred / runs，并把 `source` 与 `bounds` 带回响应。

### 3.4 `period()` 改动

1. 默认截止日 = `bounds.effective.end`（不再用 runs 的 `latest_common_date` 兜底）；
2. 默认区间仍为 180 天（可被请求覆盖），但快捷区间由前端按 bounds 锚定；
3. 上限：`MAX_PERIOD_TRADING_DAYS = 420`（覆盖 414 天全测试集），非均值方法上限同步放宽到 420，但保留非均值路径的单次计算量保护（见 K3）；
4. 调 `simulate_period` 时传入 `benchmark_closes`（新参数）；
5. `simulate_period` 输出扩展：
   - `daily[]` 增加 `market_value`、`exposure_pct`、`benchmark_return_pct`、`excess_return_pct`；
   - `months[]` 增加 `benchmark_return_pct`、`excess_return_pct`、`realized_pnl_amount`、`unrealized_pnl_amount` 月末快照；
   - `summary` 增加 §D5 全部指标（`None` 表示不可算）；
6. 响应增加 `source` / `bounds` / `benchmark: {"symbol": "000300.SH", ...}`。

### 3.5 `rolling()` 改动

1. 数据源同 `_history_rows`（pred 优先）；
2. 新增 `capital` 参数（默认 `DEFAULT_PERIOD_CAPITAL`）；
3. 新纯函数 `simulate_daily_rotation(days, picks_by_day, closes, capital, benchmark_closes)`：
   - 每日收盘把全部权益等权分给当日 TopK（缺价标的跳过并减少当日分母）；
   - 次日收盘结算全部持仓；最后一日持有为未结算浮动；
   - 输出 `batches[]`（entry_date/exit_date/positions/priced/return_pct/pnl_amount/equity）、`daily[]`（equity、market_value、cash、benchmark/excess）、`summary`（§D5）；
4. `compute_rolling_performance` 的「连续在榜」部分保留，但改名/改义为 `streaks`（只服务名单列与退出明细），**不再产出交易胜率**；
5. 响应 `summary.performance` 改为新口径，并新增 `source` / `bounds` / `benchmark`。

### 3.5.1 每只标的格子的统计块（新增，用户 2026-10-21 追加）

滚动建仓每个「股票格子」在现有 `score / pct / coverage / held_days / industry / market_cap_yi` 之外，增加 `stats`：

| 字段 | 含义 |
|------|------|
| `appearances` | 本窗口内在榜天数 |
| `streak_days` | 当前连续在榜天数（= `held_days`） |
| `first_seen` | 本窗口首次入选日 |
| `since_first_pct` | 首次入选日收盘 → 窗口最后收盘 |
| `next_day_avg_pct` | 该股在本窗口所有在榜日的**次日平均收益**（日频口径） |
| `next_day_win_rate_pct` | 次日收益 > 0 的占比 |
| `next_day_samples` | 上述样本天数（只统计有次日收盘的在榜日） |
| `next_day_std_pct` | 次日收益标准差（样本 < 3 时为 `None`） |
| `latest_close` | 窗口最后收盘价 |
| `change_pct` | **该股当日涨跌幅**（当日收盘 / 前一交易日收盘 − 1） |

**每个日期列顶部的大盘情况**（`columns[].market`）：

| 字段 | 含义 |
|------|------|
| `change_pct` | 当日沪深 300 涨跌幅 |
| `close` | 当日指数收盘 |
| `ma20_deviation_pct` | 指数收盘相对 20 日均线偏离（大盘位置） |
| `position` | `above_ma20` / `below_ma20` / `unknown` |
| `tone` | `up` / `down` / `flat`（前端红涨绿跌） |

- `change_pct` 需要窗口首日的前一交易日收盘价：`_close_history` 起点向前多取 10 个自然日（仅多一次轻量读取），指数同理；
- 全部由已加载的窗口收盘价序列计算，不新增逐股行情请求；
- 缺价标的不进 `next_day_*` 分母，`None` 前端显示 `—`；
- 该统计只描述「该标的在本窗口的名单表现」，不是组合损益，也不参与组合胜率。

### 3.6 API

| 端点 | 变更 |
|------|------|
| `GET /api/v1/models/blends/{id}/bounds` | 新增，返回 §3.3 结构 |
| `GET .../period` | 新增 `source`/`bounds`/`benchmark`；summary/months/daily 扩展；`MAX_PERIOD_TRADING_DAYS=420` |
| `GET .../rolling` | 新增 `capital`（默认 1000 万）、`source`/`bounds`/`benchmark`；performance 改新口径 |
| `GET .../dates` | 保持现状（runs，服务当日榜单/纸面台账），不承载历史统计 |

错误码沿用 `BlendError`：`pred_unavailable`（pred 解析失败但 runs 可用时自动降级，不报错）、`quote_source_unavailable`（价格为 0 或缺失超阈值）。

### 3.7 缓存

- `_range_cache` 键加入 `source` + pred 文件指纹（path+mtime+size 的 sha256）；TTL 120s 不变；
- pred 聚合结果另设进程内 LRU（32 条，TTL 120s），避免同一区间被周期/滚动重复扫；
- `bounds` 结果缓存 60s。

## 四、前端设计

### 4.1 周期收益面板

- 顶部数据源徽标：`测试集 pred · 2025-02-05 起`（tooltip 说明与 runs 等价）；降级 runs 时显示 `推理运行记录 · 2026-08-27 起` 警告色。
- 指标区改为四块：
  1. **收益**：区间收益、基准、超额、年化；
  2. **盈亏拆分**：已实现（金额 + %）、浮动（金额 + %）、合计（恒等式校验）；
  3. **风险**：最大回撤（峰/谷日期）、年化波动、Sharpe、Sortino、Calmar、信息比率；
  4. **交易**：已结算笔数、胜率、盈亏比、盈利因子、平均持仓天数、换手、平均暴露。
- 月度表新增列：基准、超额；金额列拆「已实现/浮动」。
- 快捷区间锚点从 `/dates` 改为 `/bounds.effective.end`，新增「1 年」档。
- A 股红涨绿跌；缺失 `—`。

### 4.2 滚动建仓面板

- 顶部新增资金输入（默认 1000 万）与数据源徽标。
- 主成绩改为：区间收益、基准、超额、已实现、浮动、合计、最大回撤、Sharpe（窗口样本短时标注「样本 N 日」）。
- 「连续在榜」只保留为名单色块与 `held_days`；原胜率/平均收益标签删除，避免把名单变化当交易。
- **每个股票格子**：在代码/名称下加当日涨跌幅（红涨绿跌）、在榜天数、自首次入选涨幅、次日平均收益/胜率（样本数）；悬浮显示完整 `stats`。
- **每个日期列顶部**：日期 + 大盘（沪深 300）当日涨跌幅 + 收盘 + 相对 20 日线位置；大盘涨跌幅同样红涨绿跌。
- 新增「每日批次」明细表：入选日、结算日、只数、有价数、批次收益、批次盈亏、累计权益。
- 日线表新增基准与超额列。
- 文案只用「入选/退出/持有/换仓/批次」；不出现买入/卖出/加仓/减仓/清仓。

### 4.3 类型与测试

- `electron/src/services/modelBlendService.ts` 扩展 `PeriodResponse` / `RollingResponse` / `BlendBounds`。
- 新增 `portfolioMetricsModel.ts`（纯函数：格式化、红绿 tone、指标分组），配单测。
- 面板测试覆盖：数据源徽标、已实现/浮动分栏、基准/超额、缺失 `—`、红涨绿跌、合规字眼。
- 合规源码扫描名单加入 `components/combo/PeriodReturnPanel.tsx`、`RollingBuildPanel.tsx`、`portfolioMetricsModel.ts`，只拦「买/卖」单字（combo 允许「建仓」）。

## 五、性能预算

| 场景 | 目标 | 中止线 |
|------|------|--------|
| pred 聚合 414 天 × 13 成员，冷启动 | ≤ 30s（实测 8.6s / 2.63GB） | > 90s |
| 同一区间命中缓存 | ≤ 1s | > 5s |
| 峰值 RSS 增量 | ≤ 2GB | > 4GB |
| 周期模拟 414 天 × 50 持仓 | ≤ 5s | > 15s |
| 前端首屏（stats 返回后渲染） | ≤ 300ms | > 1s |

## 六、Kill criteria（开工前预设，命中即停/回退）

- **K1 等价性**：pred 与 runs 重叠日的 Top-50 名单逐日重合 < 95%，或 Spearman < 0.99 → 停，不改数据源。
- **K2 性能**：414 天冷启动 > 90s（连续 3 次）→ 停，回退 runs 并只做指标扩展。
- **K3 内存**：峰值 RSS 增量 > 4GB 或触发 OOM → 停，非均值方法退回 120 天上限。
- **K4 覆盖率**：pred 区间内可评分交易日占比 < 90% → 该区间标 `partial_data` 并给出具体缺口日；< 70% → 拒绝计算（422）。
- **K5 基准**：沪深 300 覆盖率 < 95% → 基准/超额全部 `—` + 警告，不得用 0 或另找代理指数。
- **K6 恒等式**：`已实现 + 浮动 ≠ 期末权益 − 初始资金`（容差 0.01 元）→ 视为实现缺陷，测试必红，禁止上线。
- **K7 合规**：展示面出现买/卖字眼 → 测试必红。
