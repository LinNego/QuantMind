## 0. 结论摘要（含一处自我修正）

初查把「TTM 含未公告季报」记为 4.1% 的行覆盖率；深查分量公告日后修正为 **0.043%**。
原因：7,072 个命中行里 98.9% 的分量公告日 ≈ 报告期后 **391 天（整一年）**，是供应商 `m_anntime`
回填错位（把后一年的公告日贴到前一年同期），方向上属于「晚标」，不构成经济意义上的未来函数。
真正像延迟披露的只有 75 行，全部落在 2020 年疫情年报延期窗口（71 行）+ 北交所 2021（4 行）。

| # | 问题 | 性质 | 实测影响 | 级别 |
|---|------|------|----------|------|
| 1 | 财务 TTM 含未公告季报 | 代码缺守卫（潜在未来函数） | 真污染 75 行 / 0.043%，集中在 2020-04~06 | P2 |
| 2 | 前复权含未来分红 | 数据口径未来函数 | 300 中仅 `VWAP55`、`f13_1240` 实质，测试期相关≈0 | P1 |
| 3 | 退市股缺失 | 幸存者偏差 | 13 库 0/7 抽查；基础四表已回补 250 只 | **P0** |
| 4 | ST 未过滤 | 样本污染 | top10% ST 8.5% vs 全市场 4.0%（2.1×） | P1 |
| 5 | 板块/概念成员单快照 | 前视/幸存者 | 4/300，含 SHAP 第 1 `concept_exposure_top1` | P1 |
| 6 | 选型窗与测试期重叠 | 选择偏差 | 35.2%；选中 \|IC\| 比未选高 27% | **P0** |
| 7 | `close_fwd` 跨分区锚点 | 评估口径 | 只影响评估中心 IC，不影响选型 | P2 |
| 8 | `return_Nd` 后视列 | 物化层遗留 | 未进入 300 | P2 |

**一句话**：现役 300 的 test IC 0.179 不是靠未来函数撑起来的；两处泄漏在测试窗都近乎消失。
真正需要回答的是「剔掉幸存者偏差、ST 污染、选型重叠后，IC 还剩多少」——这是 Phase A 的任务。

## 1. 处置原则

1. 先修**会改变结论的偏差**（幸存者、选型窗），再修**数据卫生问题**（TTM 守卫、复权、排序）。
2. 每阶段先立 kill criteria 再开工；不达标就停，不追加投入。
3. 所有重物化写新目录/新分区，旧产物保留可回滚；旧模型不删，作为 v1 对照。
4. 不动实盘开关、不改模型架构、不做多模型融合。
5. 现役模型**不必停用**：测试期无实质泄漏，偏差影响的是「IC 的真实性」，不是「信号当下的计算」。
   若 Phase A 显示 IC 大幅缩水，再降级为模拟盘。

## 2. Phase A — 决定性实验（先做，1–2 天）

目标：量化「IC 0.179 里有多少是偏差」。这是决定后续是否值得投入的唯一实验。

### A1. 退市股覆盖核验 + 库补齐

- 抽查 600485 / 002450 / 000939 等退市股是否已在 `daily_forward` / `daily_backward`。
- **优先增量补写**：只对缺失的 250 只退市股、在其存续期内重算并写入 12 个因子库分区（不是全量重建）。
- 若 materializer 不支持按 symbol 补写，退化为全量重建（成本最高，需先报工时）。
- 若回补被夜间全量重写覆盖：加「退市股写入保护」（独立分区或重写后自动比对）。
- **判据**：2016-01 横截面标的数从 2355 提升到 ≥2700；抽查退市股日线完整、因子非空。

### A2. 选型窗回退

- `backend/scripts/select_training_features.py` 默认窗 `2025-09-01..2026-09-10` → 改为 `≤2025-12-31`（valid 起点之前）。
- 重跑选型，产出新清单（保留旧清单，按日期归档）。
- **判据**：新旧清单重合度 <70% ⇒ 选择偏差显著；>85% ⇒ 影响有限。

### A3. 重训对照

- 同架构、同切分、同 seed，用 A2 的新 300 重训一遍。
- **判据（kill criteria）**：
  - 新 test IC **< 0.10** ⇒ **封路**：300 特征路线不成立，停止后续投入，重估特征体系；
  - **0.10–0.15** ⇒ 可用但需下调预期与仓位；
  - **> 0.15** ⇒ 通过，进入 Phase B。

## 5. 风格问题（回答「涨时超额为负、跌时超额为正」）

这不是 bug，是 **beta=0.672 的低波价值组合**的机械结果：上涨市捕获不足、下跌市抗跌。

三个选项：

- **A 接受并披露（推荐）**：定位为防御型策略，展示层写明 beta/风格暴露，仓位按 beta 折算。
- **B 风格中性化**：训练标签对 6 个风格（amt_log / idio_vol / vol_std / turnover / mom / bp）做截面中性，
  或组合层加风格约束。单开实验 E2 比较 IC 与超额。
- **C 分域建模**：按市场状态切换模型。成本最高，不建议先做。

**判据**：B 若中性化后 test IC >0.10 且超额波动下降，则采用；否则回到 A。

### A1 前置发现：退市股回补被夜间全量重写清空

- `daily_forward/daily_backward/daily_unadjusted` 在 `quantdb_daily_sync.py` 的 `FULL_REWRITE_V2_DATASETS` 中，每晚整分区重写，只含当前在市 universe。

- **A1 的验收判据必须改为「跨夜后仍保持」**：先修写入通路（重写保留既有退市 symbol，或把回补排到重写之后并加校验），再谈补 12 个因子库；否则补库成果同样只能存活一晚。
- `valuation` 不在重写集，2026-10-21 的回补仍在。

### A1 修复设计（2026-10-22 用户拍板方向：独立仓 + 同步后写回）

- **独立仓**：`data/quantdb/1_kline_data/daily_{unadjusted,backward,forward}_delisted/dt=*/data.parquet`，
  一次性由 `backfill_delisted_daily.py` 的 baostock 缓存构建（复用 `delisted_raw/` 与 manifest）。
  该目录不在 V2 目录清单内，同步器永不触碰。
- **写回点**：`quantdb_daily_sync.run_daily_sync` 的 Phase 1 `sync_parquet()` 之后、Phase 3 Qlib 缓存之前。
  不做独立 cron——夜间同步结束时间会漂（本次 00:55–02:07），且手动 `--full` 跑也必须覆盖。
- **写回规则**：只增不改、symbol 级去重、上游优先。主表已有的 symbol 一律保留主表行；
  独立仓只补主表缺失的 symbol。`.part` 原子替换，重复执行行数不变（幂等）。
- **范围**：仅三张 K 线表；`index_daily` 无关；`valuation` 不在重写集且回补仍在。
- **失败隔离**：整段 try/except 记录状态、不打断同步（照抄 `l1_ohlcv_backfill` 的处理）；
  独立仓缺失时 no-op；上游下载失败的分区不新建文件，避免掩盖下载故障。

**两个已核实的实现约束**：

1. `verify_content`（`quantdb_daily_sync.py:191`）比对的是**本地文件哈希**，写回后必然不等于上游 sha →
   下一轮会重新下载该分区。这三张表本来就按夜全量重下（实测 2550–2621/2621），无实质新增成本；
   但健康检查须把「本地 ≠ 上游」标为预期，不能当 drift 告警。
2. **复权口径**：退市股 qfq/hfq 全部来自 baostock，单只股票内部自洽（收益/动量类因子可用）；
   但 qfq 锚点在各自退市日，与在市股（锚在今日）不可做跨股票价格水平比较。
   禁止逐行混源——同一 symbol 整段只取一个来源。

**验收（替代原「标的数 ≥2700」）**：

- 写回当晚：250/250 捕获；各分区无重复 symbol；主表 symbol 的行数与写回前一致。
- **连续两晚夜间重写后仍 250/250**（核心判据）。
- 抽样 3 日 × 3 表：`rows == upstream_rows + injected_rows`。
- 13 个因子库的补库排在此之后另做：库分区不参与夜间全量重写，补完即持久。
